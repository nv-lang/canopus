# doc: документы репозитория

Правила разработки — в [Каноне](canon/README.md). Задачи — в `tasks/NNN-<слаг>/`. Режимы работы пульта (тексты для хаба) — в [routes/](routes/README.md).

## Где что лежит (настройки и данные пульта управления)

Решение — [ADR-0016](canon/decisions/ADR-0016-config-layout.md) (владелец, 2026-10-29); подробности и команды — раздел «Where things lie» в [src/server/README.md](../src/server/README.md).

Корень экземпляра — папка выбранного файла: по умолчанию `~/.canopus/config.json`, другой файл выбирается `--config <файл>`. Плагин независимо выбирает `~/.canopus/plugin/config.json`; его состояние хранится рядом с этим файлом. Действующий контракт — [configuration.md](canon/configuration.md).

| Где | Папка или файл | Назначение |
|---|---|---|
| приложение | `config.json`, `secrets.json` | глобальные настройки и отдельные секреты |
| приложение | `data/` | проекты и сессии |
| приложение | `state/`, `cache/`, `tools/`, `backups/` | состояние, производные данные, инструменты, резервные копии |
| плагин | `plugin/config.json` | регистрация проектов и глобальные defaults |
| плагин | `plugin/data/`, `plugin/state/`, `plugin/cache/` | координация, диагностика и производные данные |
| проект | `.canopus/config.json` | настройки приложения для этого проекта |
| проект | `.canopus/plugin/config.json` | настройки плагина для этого проекта, включая выбранный профиль |
| проект | `<tasks_dir>/`, по умолчанию `doc/tasks/` | общие задачи приложения и плагина: документы и приватное состояние |
| без проекта | `~/.canopus/tasks/` | общие задачи без проекта |

Приоритет от слабого к сильному: **значения в коде → глобальный конфиг → проектный конфиг**.
Объекты объединяются, массивы заменяются. `local.json`, глобальный `local`, переменные окружения и `--set` не создают
дополнительных слоёв. Секреты читаются отдельно. Проектный конфиг плагина действует из основной рабочей копии без
коммита; ветка исполнителя не заменяет его. Запись из интерфейса видна в Git diff, автокоммита нет.

Явный переход старых личных слоёв — `scripts/migrate-two-level-config.py`, сначала без `--apply`; исходные файлы
сохраняются в проверенной резервной копии. Конфликт локальных изменений блокирует перенос без потери данных.
