# Процедура закрытия учёта задачи 253 после установки 257

Применяется после независимой приёмки и установки плагинного этапа 257, согласованного обновления main и перезапуска
сервиса владельцем; готовность продукта Crew для этой процедуры не подменяет и не заменяет приёмку плагина. Живой state не правится
руками: каждый шаг — штатное действие плагина, всё пишется в историю задачи и log.md.

Опубликованный результат 257 — `f8b08227f57e5a785adcc5ad78ecd3af938cb609`; публикация сама по себе не означает
установку в работающий сервис. Перед этой процедурой нужны согласованное обновление основной копии, перезапуск
владельцем и проверка интегратором после сообщения «перезапустил» (`crew_doctor`, наличие `target` в `crew_help`).
Переустановку, перезапуск и обновление main эта инструкция сама не разрешает.

При подготовке инструкции выполнено только чтение `crew_task {action: "show", n: 253}`: задача на приёмке,
приёмщик назначен, старая предпроверка идёт на `6b7be5e`, замка нет. Это снимок, не предположение о состоянии после
установки: перед исполнением повторить `show`. Исполняют интегратор и назначенный независимый приёмщик **253**,
не исполнитель 257. Если приёмщик недоступен, сначала штатно восстановить/передать приёмку через интегратора.

Слово владельца в шаге 1 — отдельное, с датой и источником (применение привязки к живому учёту согласуется после
приёмки 257, по границам задания).

1. Интегратор привязывает репозиторий результата (каталог — локальный клон пакета результата; ветка — `main`):

   ```
   crew_task {action: "target", n: 253, dir: "<локальный клон nova-alula>", remote: "origin", branch: "main",
              word: "<слово владельца дословно с датой и источником>"}
   ```

   Плагин проверяет: каталог — git-репозиторий, не репозиторий постановки; remote `origin` есть (его адрес записывается
    свидетельством); ветка `main` есть на remote. Живая предпроверка 253 (если есть) устаревает сама — это правильно:
    она строилась по репозиторию постановки.
    Сверить URL с публичным пакетом `https://github.com/nv-lang/nova-alula`, а не с репозиторием CrewHarness.
    Снятие/перепривязка — не способ обойти отказ проверки; при смене URL нужна новая подтверждённая привязка.

2. Приёмщик 253 начинает предпроверку — основой станет вершина `main` репозитория результата, а не CrewHarness:

   ```
   crew_task {action: "precheck", n: 253}
   ```

3. Независимый приёмщик завершает обязательные acceptance checks задачи 253 штатными `check` и проверяет полный CI пакета на точном кандидате; сохраняет свидетельство
   (repo URL, `origin/main`, SHA кандидата, команда и результат CI, основа из шага 2).
   Факт публикации и строка `result` сами по себе независимый CI не заменяют. Затем он завершает предпроверку
   опубликованным кандидатом (пакет уже на `main` и в теге; вливание не нужно):

   ```
   crew_task {action: "precheck", n: 253, candidate: "c040a9b53a329c349f0d121c8a5c41f5067f82dd",
               result: "независимый полный CI <repo URL/ref/SHA, команда и свидетельство>; опубликован: main nova-alula и v0.28.0"}
   ```

    Кандидат может быть старше текущей основы в репозитории пакета, но он — предок вершины `main` на remote: запись становится
   зелёной с отметкой «опубликован». Если вершина ушла вперёд — предпроверка просто повторяется (начать заново,
   кандидат тот же).

4. Приёмщик фиксирует учёт под замком (вливания нет, плагин перепроверяет актуальность базы, URL/ref/SHA и факт публикации
   под замком вливания проекта и общим замком публикации в цель). Замок координирует участников протокола плагина,
   но не блокирует внешние прямые git push или сторонние CI:

   ```
    crew_task {action: "merge", n: 253}
    ```

    При отказе из-за сдвига вершины/смены привязки не выполнять accept: повторить предпроверку на актуальной основе,
    при необходимости обновить свидетельство CI. Не делать merge/push в пакет или CrewHarness вручную: результат уже опубликован.

5. Приёмщик принимает с коммитом публикации:

   ```
   crew_task {action: "accept", n: 253, commit: "c040a9b53a329c349f0d121c8a5c41f5067f82dd"}
   ```

   Плагин проверяет, что коммит входит в `main` репозитория результата; запись сохраняет привязку, отметку
    «опубликован» и вершину принятия (`accepted_on`). Перечитать `show` и убедиться, что принят именно указанный SHA.
    `cleanup` — отдельная уборка по возвращённому инструментом списку: только после её согласования; сохранённые
    доказательства и деревья не удалять автоматически. При отложенной уборке оставить задачу принятой, без cleanup.

Чего процедура не делает: не меняет nova-alula (код, main, тег), не вливает несвязанные истории, не правит state
вручную, не отменяет 253.
