## Предварительный обзор (проверено поиском, 2026-11-14)

| Инструмент | Opensource | Репозиторий | Лицензия | Стек |
|---|---|---|---|---|
| Codex CLI | да | github.com/openai/codex | Apache-2.0 | Rust (~96%), самодостаточный бинарник |
| ZCode (Z.ai) | да | github.com/zai-org/ZCode | Apache-2.0 | TS/Node, Electron + web + TUI вокруг единого agent runtime |
| DeepSeek harness (`dsh`) | да (developer preview) | github.com/deepseek-ai/deepseek-harness | MIT | TS-монорепо, «всё есть плагин» на движке Cordis |
| Claude Code | частично | CLI закрыт; anthropics/claude-code (docs/issues/devcontainer) и Claude Agent SDK (TS/Python) открыты | SDK MIT | — |
| Qoder | нет | продукт закрыт; org «QoderAI» на GitHub — сторонний проект с тем же именем, не Alibaba; смежное: open-code-review от Alibaba | — | — |

**Приоритеты по полезности для Канопуса (рекомендация):**
1. **ZCode** — наш собственный хост: `packages/rpc` + `packages/client` (SDK клиента агента — сверить с нашим ACP-клиентом из 095), `packages/provider` (абстракция провайдеров — второй/третий агент-бэкенд), `architecture-policy.yaml` + `.architecture-baseline.json` (механизм политики архитектуры — образец для наших стражей/Канона), UI plugins, каталог skills. Права на код — Apache-2.0.
2. **Codex** — эталонные механизмы: модель sandbox/approval (read-only / workspace-write / full + approval policy) — сверка с нашими стражами и страж-таблицей (черновик 299), session rollout-файлы (сравнение с нашим журналом), конфиг/профили. Код на Rust — берём идеи и протоколы, не строки.
3. **Claude Agent SDK** (открытая часть) — compaction, subagents, hooks, permission modes как справочник механизмов; их инженерный блог о long-running harness.
4. **DeepSeek harness** — только идеи плагинной архитектуры (Cordis); developer preview с ломающими изменениями — код не брать.
5. **Qoder** — вычеркнуть: opensource нет.

**Шаги:**
1. Shallow-клоны в `%TEMP%` (только чтение, как при разборе kimi-code); по каждому — docs + карта структуры.
2. Сверка с Канопусом: что уже есть (Канон, машины, `src/`), что формализовать, что взять как идею/эталон, что не нужно.
3. Итоговый документ в этой папке: по каждому репозиторию — находки с путями к файлам и рекомендацией; из находок — предложения на отдельные черновики задач (как 296–299 выросли из разбора kimi-code).

**Результат:** документ разбора в этой папке + список предложений на подтверждение. Реализация — отдельными задачами после слова владельца.

**Приёмка:** владелец по документу разбора.

**Границы:** приватные имена/пути — через стражи; репозитории только читать (правило 16 Канона); код брать только с совместимой лицензией (Apache-2.0/MIT) и с атрибуцией по правилам лицензий.
