# 300. Разбор opensource-харнессов — что взять, что не брать

Дата: 2026-11-14. Метод — как в разборе kimi-code (296/297): shallow-клоны только для чтения, находки с путями,
сверка с четырьмя линиями Канопуса: **(a)** ACP-клиент и вторые агент-бэкенды, **(b)** стражи и политика,
**(c)** передача контекста между окнами (298), **(d)** жизненный цикл задач и Канон. Разбор выполнен четырьмя
исследовательскими сессиями по одному репозиторию; их полные отчёты — в истории окна. Согласования — владелец,
2026-11-14, чат («согласовано», «по рекомендации»).

Репозитории: `openai/codex` (Apache-2.0, Rust), `zai-org/ZCode` (Apache-2.0, TS — наш хост), `deepseek-ai/deepseek-harness`
(MIT, developer preview), открытые части Claude Code (`anthropics/claude-code` + Claude Agent SDK). Qoder — закрыт,
исключён (план задачи).

## 1. Codex (`codex-rs`)

| Находка | Где | Суть | Линия |
|---|---|---|---|
| Провайдер как запись данных | `model-provider-info/src/lib.rs` | провайдер = TOML-запись: id, base URL, каталог моделей, **вид** учётных данных (env/bearer/команда/OAuth), исход перебоя авторизации как самовосстановимый контракт | (a) |
| Именованные профили | `config/src/profile_toml.rs` | профиль = модель + провайдер + approval policy + sandbox + усилие одним переключаемым узлом | (a) |
| Стек конфига с провенансом | `config/src/config_layer_source.rs` | каждое значение несёт источник слоя; admin-слой `requirements.toml` перекрывает пользователя; слияние типизировано (конфликт — ошибка, не тихая победа) | (d) |
| execpolicy — декларативные правила команд | `execpolicy/src/policy.rs`, `rule.rs` | префиксные правила по первому токену, три исхода **Allow / Prompt / Deny**; `Prompt` = спросить, не заблокировать | (b) |
| Хуки с трёхзначным исходом | `hooks/src/types.rs` | Success / FailedContinue (лог и дальше) / FailedAbort; вышележащий слой **не может переписать** включение хуков нижележащего | (b) |
| Rollout-файлы | `rollout/src/lib.rs`, `history/src/lib.rs` | сессия — append-only JSONL типизированных записей (meta, turn context, usage, Compacted…); resume и fork с `forked_from_id`; сканер хвоста без чтения всего файла | (c) |
| Протокол app-server со схемами | `app-server-protocol/src/rpc.rs` | типизированные запросы/события, генерация JSON-Schema/TS — клиент не расходится с сервером | (a) |
| Sandbox × approval — ортогональны | `protocol/src/config_types.rs` | «что может делать» и «о чём спрашивать» — два независимых регулятора на профиль | (a),(b) |

**Не брать:** 90-крейтный воркспейс и Bazel/Nix; их нестандартный JSON-RPC (наш клиент говорит стандартом);
автоматику учёток OpenAI — брать только форму интерфейса провайдера.

## Сводка: пять сквозных идей, которых нам не хватает

- **И1. Исходы стражей — закрытый словарь данных** (Codex `Allow/Prompt/Deny` + их трёхзначные хуки; CC SDK
  типизированная карта; dsh закрытые исходы): в `guards.md` дополнить колонку «исход» (блок / спросить владельца /
  наблюдать) и зафиксировать «Prompt = вопрос владельцу с рекомендацией» — у нас эта форма уже есть.
- **И2. Слои без переписывания** (Codex провенанс-стек и запрет переписывать хуки нижнего слоя; ZCode доверие по
  дайджесту на сессию; CC SDK MDM-слой без люка): правило для Канона — вышележащая настройка не включает/не
  выключает стражи нижележащей; изменение конфигурации хуков не задевает идущие сессии.
- **И3. Внешний эффект после durable записи** (dsh чекпоинт-барьеры, «исход неизвестен» без авто-повтора; ZCode
  явный `discarded` вместо авто-реплея): одна строка в Канон рядом с П2 из 301.
- **И4. Spill-словарь для 298** (dsh spill; Codex rollout-fork с `forked_from_id`; CC SDK fork по message-id):
  спецификация 298 дополняется «превью + указатель» вместо молчаливой обрезки и происхождением переноса.
- **И5. Бэкенд как запись данных + явное отвержение возможностей** (Codex provider/profile; dsh ACP-шов; ZCode
  resolver): продолжение 296 — второй агент = запись в настройках (уже так и есть), дополнить проверкой
  «неизвестная возможность агента = ошибка, не тишина».
