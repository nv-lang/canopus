## Критерии приёмки

1. Новый folder spawn с валидным parent сохраняет task.parent/order.child, авторство/историю/идентификаторы и последующее штатное распространение статуса. Invalid project/target/order identity, чужой integrator/worker и конфликтующие связи отвергаются до создания task/session/ветки или иных частичных эффектов. Folderless supported path не регрессирует.
2. Есть штатная документированная reconcile/attach команда для существующей пары с проверяемым основанием. Она сохраняет goal/criteria/history/acceptance/commit/merged_head/evidence/rework/route/cycle и не меняет чужие роли/lock/ветки. Повтор той же пары идемпотентен; wrong-parent/duplicate/conflicting attach/race и устаревшая expected version fail-closed, с отсутствием частичного ложного done; историю обеих сторон и причины отказа можно проверить.
3. Синтетические 112→129 done и 113→133 done закрывают только доказанно выполненные заказы, без fake accept/cancel. Синтетическая 114→140 reviewing/blocked лишь восстанавливает связь и оставляет заказ открытым/ребёнка не-done. Невыполненный/cancelled/недоказанный ребёнок не выдаёт выполненный заказ. Реальная metadata всех проектов не читается/не меняется для тестов.
4. RED на потере parent и отсутствии безопасного reconcile, затем GREEN минимум на позитив/неверную identity или права/конфликт или повтор. Тест crash/частичной записи и межпроцессной гонки либо обоснованный fail-closed механизм. Guard полного outside-tree/проектных полномочий не ослаблять; Unicode/short-path фикстуры изолировать и канонизировать внутри теста, не менять реальные пользовательские каталоги.
5. Полный npm test opencode-plugin, targeted и guards через очередь машины, независимая приёмка и свежий линейный exact-candidate CI/precheck/merge, без merge commits. Прямой запрет full rerun 140 относится к 140 и не отменяет обязательный полный набор ЭТОЙ новой задачи. Никаких fake GREEN/CI waiver/merge_precheck off.
6. Действующие README/help/schema согласованы с кодом. Подготовлены точные безопасные команды для последующего применения Nova 112/113/114 после отдельной принятой активации, с explain/dry-run и ожидаемыми состояниями/evidence; по возможности один авторитетный применяющий интегратор, без смены ролей ради обхода. Это инструкция, не выполнение над реальными карточками.
