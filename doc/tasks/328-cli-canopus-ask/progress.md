- `canopus ask` использует порт выбранного инстанса и протокол веб-панели `/ws?history=lazy`. Находит или создаёт сессию, ждёт подтверждения выбора модели и стримит ответ по идентификатору хода из квитанции. Текст ответа идёт в stdout, ID новой сессии и диагностика — в stderr. Для продолжения достаточно `--session`. Если указан `--agent`, он должен совпадать с агентом сессии.
- Коды выхода: 0 — ход завершён, 2 — ошибка команды или конфига, 3 — ошибка установления связи, 4 — отказ до начала хода, 5 — ошибка хода или потеря связи после отправки. Диагностика сохраняет `code` из ошибки API и причину отказа агента. TCP-подключение и HTTP Upgrade ограничены 10 секундами каждое. Дедлайн хода ведёт хаб.
- Проверки на Oracle 0.1.7: юнит-тесты клиента. Проба транспорта на loopback проверила отказ без слушателя, таймаут молчащего слушателя и отсечение событий чужого хода. Проба собранного CLI с отдельным хабом и тестовым агентом проверила коды 0/2/3/4/5, две модели, продолжение сессии и получение фрагмента stdout до выхода процесса. Клиент WebSocket получил сообщение CLI в ленте этой сессии и отправил своё сообщение в неё.
- Выбор модели и отправка остаются двумя сообщениями протокола страницы. Изменение модели другой вкладкой между ними может повлиять на ход.
- Git-страж проверил формат и секреты. Для проверки подключения хуков в PATH указывался рабочий интерпретатор `python3` под именем `python`. При первой попытке Git-страж отклонил коммит из-за отсутствия штатного списка запрещённых имён. Перед повторной попыткой список установили на selectel.
