# 302. ACP-шов: неизвестная возможность агента — явная ошибка, не тишина (И5)

**Статус:** черновик (создан по слову владельца; до подтверждения в приложении номера и папка условные).

**Инициатор и разрешение:** владелец, 2026-11-14, чат окна агента («по рекомендации») — на находку И5 из задачи 300 (разбор opensource-харнессов). Отдельной задачей — по рекомендации исполнителя (не сливать со стражами 301: это шов `src/acp`, не страж).

**Проверка дублей:** хвост каталога задач и черновики 296–301: 095 — сам ACP-клиент (база), 296 — проверка совместимости kimi acp; явной политики «неизвестная возможность = ошибка» у клиента нет.

**Цель:** при рукопожатии с агентом (`initialize`, `session/new`) клиент сверяет заявленные возможности агента с тем, что понимает сам, и на незнакомое отвечает явно — ошибка связки или вопрос владельцу, а не молчаливое опущение.

**Образец:** `deepseek-ai/deepseek-harness`, `packages/subagent/subagent-acp` — «the seam rejects unsupported start-time capabilities rather than silently omitting them» (задача 300, И5).

**Что нужно:**
1. Инвентаризация: какие поля capabilities агентов наш клиент читает (`src/acp/client.nv`, `project.nv`), какие молча игнорирует (известный пример — `session_info_update` kimi уже «skipped» в проекторе, задача 296).
2. Правило в `src/acp`: незнакомые критичные возможности (например, схема elicitation, которую агент считает договорённой) — явный исход: `FailCode` связки + понятное сообщение; некритичные незнакомые поля — запись «skipped <вид>» в трассу (уже есть) и, при желании, строка в панели.
2а. **«Чтение истории по требованию»** (задача 303, раздача): сосед MCP-инструмента вопроса в хабе — инструмент `read_session` (ZCode-образец `ReadSession`), чтобы агент мог прочитать историю другой сессии сам, вместо вкладывания её в контекст; включить в объём этой задачи при подтверждении или выделить отдельной.
3. Тест в `src/acp` (fake-agent с незнакомой capability) и проба на kimi acp (после 296 — реально подключён).

**Критерии приёмки:** nova test src/acp зелёный; проба с fake-agent «подсунь незнакомую capability» даёт понятный исход, не тишину.

**Результат и куда он попадает:** код — `src/acp/`; правило — README `src/acp/`.

**Связи:** 095 (клиент), 296 (проверка kimi acp), 300 (И5).

**Границы:** не меняет протокол на нашей стороне (JSON-RPC остаётся стандартным); не трогает продукт (hub/машины) — только шов клиента.
