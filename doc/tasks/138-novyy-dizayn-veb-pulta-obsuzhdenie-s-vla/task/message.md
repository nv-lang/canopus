## Критерии приёмки

1. Визуальное направление и существенные решения согласованы непосредственно с владельцем в этой вкладке и записаны с датой/источником; интеграторские предположения не выданы за его выбор. Сначала наглядное согласование, затем реализация.
2. Новый экран заметно отличается от установленной 130 по согласованным с владельцем признакам, а не только отступами/радиусами. Есть сравнение до/после и конкретная сверка результата с принятым направлением.
3. Работающие чатовые функции, 131 model slot и 132 agent registry/134 handlers сохранены, history/backend не меняются ради дизайна. Нет fake controls, утечек, unsafe HTML или ослабления CSP.
4. Реальные desktop/узкий light/dark screenshots и browser actions; минимум три различающие пробы, включая создание/отправку/отмену или разрешение/границы layout. Полный затронутый набор через очередь, guards и signed commit с точным SHA; прежние тесты не ослаблены.
5. Независимая приёмка и линейный exact-SHA candidate CI/precheck/merge, после чего отдельное разрешение на установку. Одобрение визуального эскиза не заменяет итоговые функциональные проверки.

## Функциональный объём пульта (владелец, 2026-10-21, прямой чат)

«фуекциональномть надо смотреть в плагине под opencode, эту функциональност мы должны реализовать в пульте»
(владелец, 2026-10-21, прямой чат, опечатки сохранены). **Пульт CrewHarness — отдельный продукт; OpenCode и
плагин служат только для обкатки идей** (владелец, 2026-10-21, прямой чат: «CrewHarness пульт - это отдельный
продукт, opecode служит только для обкатки идей»). Поэтому перечень функций пульта берётся из
opencode-plugin как эталон («что продукт умеет»), но реализация — своя, в продукте (Nova, `src/server` +
`src/web`, собственные хранилище и события движка), без архитектурной привязки к файлам ящика плагина и без
зависимости от OpenCode в устройстве продукта. Инвентаризация-эталон по коду плагина (2026-10-21):

**Функции обзора команды** (эталон — данные ящика плагина `<data>/opencode/crew-harness`; в продукте — свои
источники):

- проекты и задачи под проектами (эталон `tasks/<проект>/<N>.json`): номер, заголовок, статус
  (`starting/running/submitted/reviewing/rework/approval/accepted/done/cancelled`), приоритет P0–P3,
  исполнитель, сессии задачи (`исп`, С1…С6) с шагами `k/N`, маршрут, ветка/worktree;
- состояния вкладок/сессий (эталон `status/*.json`, в плагине назван «открытым контрактом»):
  `working/owner/question/watch/reply/idle`, флаги `wait`, `gate`, `stuck`, `loop`, `sys: lost/hung`;
- полоса «ждут вас» (эталон `forms/`, `obligations/`, `gates/`): вопросники владельцу, невыполненные
  обязательства, ворота без вопроса;
- замки (эталон `roles/`): исключительные роли, замок вливания проекта;
- очередь машины и наблюдения (эталон `watches/`, лимит `machine_slots`): тяжёлые команды по очереди;
- ход и учёт (эталон `progress.log`, `log.md`, `usage.log` папок задач): вкладки «Ход» и «Учёт» эскиза 09;
- здоровье и присутствие (эталон `doctor.json`, `windows/`, `cards/`).

**Функции управления** (эталон — действия плагина):

- ответ владельца на вопросник (эталон `answers/` + `scripts/crew-answer.mjs`), решение по плану
  (эталон `approvals/` + `/plans`);
- письмо вкладке, создание задачи, push/cancel, запуск наблюдения, управление задачей по номеру
  (эталон — инструменты `crew_send`, `crew_task`, `crew_spawn`, `crew_watch`, `crew_config`, `crew_doctor`);
- в продукте каналы команд — свои (события владельца в `src/server` по образцу `user_message`/`cancel`/
  `permission_decision`), не файлы плагина.

**Разговор с агентом** (streaming, разрешения, отмена хода, история) — прежний транспорт продукта
`src/server` `/ws`; не отменяется, а дополняется функциями команды из эталона выше. У плагина нет ни HTTP,
ни WebSocket наружу (только MCP на stdio для claude-code) — и это не ограничение продукта: связывать их не
требуется, идеи переносятся в продукт по мере обкатки.

Соответствие эскизу 09: левая колонка (проекты → задачи, чипы, `k/N`, замки, статус-строка с очередью и
замком, «ждут вас») и правая (разговор с вкладкой, разрешения, выбор агента) целиком покрываются
перечисленными данными.
