2. **Обязательная связь каждого progress linePattern с unitRule исключает сессии без единиц.**

   критичность: существенная — закрытая форма не представляет две прямо предусмотренные сессии полного алгоритма и их специальный протокол завершения. Меняет допустимый регламент, полноту покрытия и REQ-19/AC-15.

   уровень: требования

   **Цитаты закреплённого источника:**

   - `task-runner.md:46`, строка КОММИТ/ПУШ таблицы единиц: «единиц нет: сессионная часть хвоста только “Сессия: `<код>`. Единиц нет: одна строка “`<код> 0/0 старт`”, строку ПРОФИЛЬ не пиши”».
   - `task-runner.md:133`: «КОММИТ, ПУШ: … Единиц нет: одна строка “`<код> 0/0 старт`”, строку ПРОФИЛЬ не пиши».
   - `task-runner.md:93`: «в строках с `0/0` слово “запуск” значит “единиц пока неизвестно”, слово “старт” — “единиц нет” (КОММИТ, ПУШ)».

   **Место спецификации:** `spec.md:50,99–101,130,249,273,504`; REQ-07, REQ-08, REQ-19; AC-15.

   **Точные нормы спецификации:**

   - Строка 50: linePattern ровно `{id:string,grammar:string,hasDate:boolean,unitRule:string}`, «все required/non-null».
   - Строка 101: «LinePattern применяется только к узлу с тем же unitRule».
   - Строка 130: «unit ненулевой у session с единицами по registry, иначе null».
   - REQ-19: «Первая строка 0/N старт, подпись≤80, последняя N/N готово».
   - REQ-07 включает КОММИТ/ПУШ в представляемые сессии.

   **Доказательство:**

   Для КОММИТ и ПУШ источник явно устанавливает отсутствие единиц. По строке 130 их узел имеет `unit:null`.

   Но объявить применимый к такому узлу linePattern невозможно:

   - `unitRule` нельзя пропустить или поставить `null`;
   - любое строковое правило обязано разрешиться в unitRules;
   - linePattern разрешено применять только к узлу с тем же правилом;
   - у законного zero-unit узла `node.unit=null`, поэтому такого правила у него нет.

   Добавление фиктивного `unit.none` не устраняет противоречие: оно требует ненулевого `node.unit` там, где собственная норма требует `null`. Существование будущего registry не отменяет эту связь.

   Кроме того, общее требование последней строки `N/N готово` не содержит исключения для специальной формы КОММИТ/ПУШ, где закреплённый хвост требует **одну** строку `0/0 старт`. Дописывание `0/0 готово` не является точным представлением указанной формы источника.

   Положительный контроль — connected-fragment: у обычного узла С1 одновременно имеются `node.unit.numeratorRule=unit.spec`, `linePattern.unitRule=unit.spec` и соответствующий элемент `nSourceRules`. Новая проблема относится не к этой исправленной counted-ветви, а к отсутствующей zero-unit ветви.

   Проба — сопоставление деклараций и точных строк методики. КОММИТ, ПУШ и runtime раннера не запускались.

   **Рекомендация исправления:** явно разделить counted и zero-unit формы linePattern/применимости, сохранить различие `0/0 запуск` и `0/0 старт`, определить исключение завершения для КОММИТ/ПУШ. Согласовать таблицу, инварианты, REQ-19 и AC-15; добавить парные данные для обеих ветвей. Не вводить новое процессное исключение: специальная форма уже дана закреплённым источником.
