## Чего хочет владелец

«тогда исправь канон и механизм крю через интегратора, чтобы рабочие вопросы решались без меня, а ко мне приходили только те, где действительно нужно мое решение» (владелец, 2026-11-01, чат оркестратора; точная передача интегратору, идентификатор ROUTING-OWNER-20261101-1224). «Рутинных повторных согласований не спрашивай» — рабочая формулировка оркестратора, не дословная цитата владельца (исправление атрибуции по письму оркестратора от 2026-11-01).

**Дополнение 2026-11-01, отдельно после исходного source checkpoint.** Дословное слово владельца: «да, согласовано» (текущий чат, передано дежурным по поручению владельца 14:24 и автором задачи 14:26). Согласовано показанное **предложение ассистента**, не произнесённая владельцем формулировка: вопрос → ответственный → допустимое умолчание → срок → явная адресная блокировка, если продолжать нельзя. В Crew — минимальная привязка qid/контекста/источника, ограниченного умолчания/срока и durable адресного blocker. Срок не разрешает owner gate/HOLD/новую работу/live/деньги/публикацию; Recommended не полномочие. Дополнение отдельным diff/commit, исходный checkpoint и его проверки не обнуляются. Общую нормативную редакцию готовит интегратор методики отдельно; pin не меняется, целей/реестра/правил находок это дополнение не вводит.

## Что нужно

Довести до подписанного неподвижного кандидата маршрутизацию рабочих вопросов и согласование Канона по уже принятому ADR и новому слову владельца. Это ОТДЕЛЬНАЯ задача, связанная с 279, а не второй исполнитель её state/delivery/HOLD diff. Новая собственная сессия/ветка/дерево Sol. Немедленно первой квитанцией автору задачи сообщить номер/session/git root/branch/HEAD и T/2T до больших изменений; затем работать, не ждать разрешения на каждый обычный шаг. Новых агентов/моделей/усилия существующих окон не менять. Дубликат перед созданием не найден.
1. Project integrator выполняет роль оркестратора ВНУТРИ методики. Цепочка исполнитель/приёмщик → ответственный task.author/актуальный интегратор проекта → владелец только для реального неразрешённого решения/closed gate. Внешний Codex-чат не обязательный посредник. Missing knowledge/path/artifact/fact-check решается командой через свой integrator, не формой владельцу и не пустым auto Recommended. При неоднозначности содержательный разбор integrator, но настоящие ворота/неразрешённые последствия не обходить. Наличие рекомендации не источник отсутствующего знания и не разрешение действия.
2. Конкретный router с qid/task/project/source/context и durable/idempotent состоянием. Новые text/form/mail requests и УЖЕ ВОЗНИКШИЕ формы получают корректную маршрутизацию без потери исходного вопроса/двойного ответа. Integrator добывает факт/зависимость, записывает проверенный источник и отвечает исходному адресату/идентификатору; owner получает лишь точное оставшееся решение. Смена integrator, закрытый старый task.author, retries/restart/late answers/уже отвеченный owner qid не создают повторного native form answer и не стирают вопрос. Актуальный ответ/решение владельца не отменяется stale integrator reply. Подтверждение маршрута/ответа не выдумывать по enqueue HTTP200. Права доверенных источников/контекста не извлекать из произвольного текста модели «владелец разрешил». Совместимость legacy unknown — безопасно/видимо.
3. Канон и role instructions/help/побудки/код согласовать. Подтверждённое расхождение: doc/canon/process.md строка402 содержит «вопросы сессий приёмки» в blanket owner list; принятое ADR-0010, второе дополнение 2026-10-19 (097), строка79 ЯВНО отменило exception для text и forms. Зафиксировать finding; входные инструкции не должны вновь вводить отменённое правило. Новое слово оформить штатным ADR/каноническими ссылками с ТОЧНОЙ цитатой/датой/источником. Owner закрытый список сохранить, answer_* и личные настройки НЕ менять. Не заменять эту работу галочкой autoanswer.
4. Естественное завершение уже ограниченного этапа — сохранить отчёт/состояние и остановиться; не спрашивать заново разрешение выполнить уже выданную границу. Продолжение ранее порученной работы в её границах тоже не новый owner gate. Новая работа/интеграция/реальный gate остаётся отдельным решением. Разрешённая диагностика после CI timeout при gate block не означает autorerun CI/merge/увеличение timeout; execution_pause/legacy HOLD не снимать.

Не отменять действительное owner approval; если gate действительно обязателен — показать точный источник и только необходимое решение, служебный адрес предоставляет команда. ## Критерии приёмки

AC-1 RED→GREEN: исполнитель и приёмщик с рекомендацией и без; missing fact/Alula не уходит владельцу и не отвечает выдуманным Recommended, получает integrator route+source-backed answer с исходным qid.

AC-3 Передача готового отчёта/сохранение состояния и продолжение уже разрешённой работы не требуют повторного разрешения; разрешённая диагностика CI при gate block остаётся в пределах. Реальные live changes/деньги/публикация/отказ от требования/новый scope и owner gates остаются владельцу; уже выданное согласие учитывается по проверяемому источнику, не слову модели.
AC-4 Кейс 087/WC-1 d7e541a проверяет provenance обоих критериев и отсутствие ложной альтернативы/перекладывания служебного адреса; genuine owner gate не обходится. Чужой репозиторий неизменён.
AC-5 process.md/instructions/help/code соответствуют ADR-0010 и новому ADR, old blanket reviewer exception не возвращается. Личные answer_* неизменны. Полные подходящие tests/guards GREEN в изоляции через queue; signed frozen candidate и независимая проверка, не только письма.
