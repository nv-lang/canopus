# 286 — Конкретное предложение перед удалением настроек

Статус: предложение владельцу; действующие настройки не удалены. Источник полномочия: владелец, 2026-11-06, чат: «согласовано 286, 287 - два параллельных исполнителя в отдельных ветках, малый путь». Обязательство показать конкретный список до удаления остаётся в согласованном плане.

## Один путь к конфигу и экземпляр

Предлагается вариант A: `canopus serve --config C:/work/instances/demo/config.json` выбирает глобальный конфиг и экземпляр `C:/work/instances/demo/`. Здесь лежат `secrets.json`, `data/`, `state/`, `cache/`, `tools/`. Стандартный путь — `<home>/.canopus/config.json`: действующие данные не переезжают. Два файла конфига в одной папке используют один экземпляр и одни данные. Проектный и личный проектный слои продолжают перекрывать выбранный глобальный файл. Корень экземпляра и стандартный пользовательский `.canopus` не должны определяться как проектный слой. Относительные пути разрешаются относительно своего файла, не текущего каталога.

У плагина стандартный файл `<home>/.canopus/plugin/config.json`; `data/`, `state/`, `cache/` — соседи этого файла. Обычная регистрация в OpenCode — только пакет. При выборе другого файла единственная регистрационная опция — `{config: "C:/work/instances/demo/plugin/config.json"}`. MCP получает тот же контекст пути через внутренний протокол запуска; это не пользовательская env-настройка. Приложение и плагин остаются независимыми. В тестах — явный API/временный конфиг, без нового env вместо CANOPUS_HOME.

Вариант B: `--config` меняет только значения, данные и секреты остаются в стандартном пользовательском корне. Для независимых экземпляров тогда понадобится дополнительное поле `data_root` либо отдельный механизм изоляции. Это сложнее правила одного входа; вариант A рекомендуется как наиболее прямой. Выбор владельца нужен до удаления прежних входов.

Глобальный плагин-конфиг оставляет `project_settings`, `defaults`, `local`, `retention_days`. Последнее — пользовательская политика срока хранения истории; прежний `keep_days` удалить как дубль. В `project_settings` остаются пути репозиториев настроек и определения виртуальных проектов `{project, root}`. Прежние `projects` и карта проектов вместо массива — явный однократный переход, постоянные aliases не читаются. Глобальные local сохраняют поправки других проектов без изменения чужих репозиториев.

```json

```

Регистрационные launch-переопределения произвольных setting-полей убрать: реальные значения должны быть в перечисленных файловых слоях, а не дублироваться в opencode.jsonc.

## Публичные входы, которые предлагается удалить

- `--home`, `--set`, `--file`, позиционный `serve settings.json`; единственный выбор источника — `--config`. Командные действия `config get/set/list`, `doctor`, флаги действия `--project/--local/--show-origin`, аргументы одноразового переноса остаются действиями, не runtime-переопределениями.
- `CANOPUS_HOME`, `CANOPUS_SERVER_CONFIG`, CANOPUS_SERVER_* для настроек, CANOPUS_STT_DIR, CANOPUS_VOICE_*, CANOPUS_PG_*, CANOPUS_PRESET, CANOPUS_TOOLS_DIR. Точный список 34 переменных из config_layout сверен в inventory.json; существование устаревшего входа диагностируется, его значение не печатается.
- Протокольные session/project/task/watch/role env, среда ОС/компилятора, переменные агентов и авторизация сторонних провайдеров сохраняются. Они не превращаются в пользовательские настройки Canopus.
- Таймеры и test-подмены плагина не становятся десятками JSON-полей: реальные constants/явные зависимости в тестах. Нужные guard/CI inputs и инфраструктурные credential inputs проверяются отдельно; они не удаляются вместе с runtime-переменными приложения.

## Переход и проверки

Перед изменением живой установки сохранить конфиги, локальные значения и индекс. Обычные файлы с удалёнными keys получают адресную диагностику и явный план перехода: defaults/вычисляемые значения удаляются безопасно; отличающиеся неподдерживаемые значения требуют решения, никогда не игнорируются. Данные, секреты, backend, подключения и выбранный профиль сохраняются.

Проверить parser/file layers/strict unknown-field errors, запуск без настроек, explicit config из другого cwd, два независимых экземпляра, два конфига в одной папке, исключение instance-home из project discovery, запуск plugin/MCP без приложения, Unicode Whisper path. Полные затронутые наборы и сборки — через очередь машины. Никаких изменений main/живого сервиса исполнителем; сдача root для последовательного вливания с287.
