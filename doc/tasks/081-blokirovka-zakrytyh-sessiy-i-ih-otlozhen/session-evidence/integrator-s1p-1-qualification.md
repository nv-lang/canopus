# Приём входов С1п-1 для независимой С2-3

Источник: собственное чтение и поздние read-only команды интегратора, 2026-10-18.
Это не утверждение спецификации и не независимая проверка её содержания.

Полностью прочитаны root analysis/spec/trace, матрица и документальные регрессии.
Редакция содержит 11 REQ / 10 AC / 6 DNC, T01–T30. По числу REQ это M, риск остаётся
высоким; снижение глубины или автоматическое разбиение не предлагается. Полноту
атомизации T01–T30, историю изменившихся ID и все writer/consumer callsites проверяет
следующая С2, не число строк само по себе. Автор раскрывает недочитанные старые
evidence/callsites; это не даёт права считать матрицу исчерпывающей без новой сверки.

Пакет из 13 существующих файлов — три root-документа и все новые evidence — побайтно
сохранён отдельно вне репозитория с manifest. Три `root-before` копии сверены с
ранним before. Сверка его 715 entries: неожиданных изменённых existing файлов нет,
четыре старых префикса log/profile/progress/usage сохранены. Generated
`.opencode/opencode.json` отсутствует после submit — отдельная динамическая оговорка;
не восстановлен, не обвинение автора и не исключение остальных config из контроля.

Версии для новой проверки:

- analysis: 8859 bytes, SHA `1920eff292b14a4d0e770395e08c6d14f149d6758200e30965cbd4b13b10ab14`;
- spec: 16231 bytes, SHA `eab33a1c3cd77cf99c696b82acb7add65b46a837a23a06e2e9881b652dc4986a`;
- trace: 12415 bytes, SHA `b2319ef51501a3b714d91e4e88740bbbcc3265ebab167849af9d5672a0c6b90e`.

Identity/digest разделены в новой редакции, но новая raw-проверка actual dossier
автором не выполнена — он прямо это пишет. Поэтому «записан правильный expected»
не означает «новая проверка actual завершена». Старый 63-символьный expected остаётся
исторической ошибкой. С2-3 проверит первичные bytes и owner partition самостоятельно.

Новые вопросы по внешней OpenCode гарантии/OS containment не решены владельцем.
HOLD не снимается, отсутствие запрета независимым клиентам нельзя замаскировать
успешным local-only тестом. При проверке отличать корректный fail-closed результат
от спецификации, которая допускает вечный STOP вместо обязательного GREEN/feasibility.
Не требовать подробного выбора всей архитектуры от spec вместо будущего плана.

С1п-1 не засчитывается независимой С2. Следующая проверка — предметный заход 3,
потолок 4, чистая серия 0. Старые С2-1/2 и ошибки не переписываются. До независимой
проверки и явного утверждения владельцем план/код/тесты/admin mutations не разрешены.
