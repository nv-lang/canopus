   без установки системных компонентов/повышения прав. Не повторять forensic intake.
2. P1, **до исправляющего кода**: воспроизвести на точных исходниках базы закрытую A
   и уже отложенную команду/watch; настоящий release/reassign/close-путь, затем
   consumer/poll. Исходный тест должен краснеть по old side effect, а не по импорту,
   недостающей зависимости или ошибке теста. Парная B положительна. Дополнительный
   old-wake/таймер не должен служить обходом; фиксировать вид реально проверенного
   effect. Сохранить driver/revision/command/exit/raw output+SHA до прототипа.
3. P2a: самый простой работающий прототип монотонного durable tombstone и проверки
   на writer/consumer/effect boundaries. Начать со штатных Node/filesystem
   возможностей без SQLite/native broker. Общая межпроцессная сериализация и
   стабильные `(O,effectID)` обязательны для соответствующих выводов. Простой
   `if closed`, один JS Set или статус CLOSED сами по себе не гарантия. Повторить
   тот же oracle; positive B и restart/stale-card не должны blanket-block-иться.
4. P2b: минимальные различающие пробы для ещё не покрытых требований: C<D/D<C,
   два consumers, crash/recovery и spawned-before-PID/descendant/write scope там,
   где выбранный простой механизм претендует на поддержку. T=120 и L не ослаблять.
   Любые процессы только свои fixture-потомки с доказанным owner/scope и конечным
   завершением. Не делать broad kill и не принимать отсутствие PID за proof.
   Если требование не обеспечивается простым механизмом — сохранить конкретный
   FAIL/reproduction и остановить усложнение до нового owner GO.
5. Отчёт: либо «простого механизма достаточно» с **раздельным доказательством**
   всех требований, на которые этот вывод распространяется, либо «нужны более

   какие REQ/AC/DNC проверены/не проверены, проверенные границы legacy/new,
