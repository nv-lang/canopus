# 296. Второй агент-бэкенд: kimi-code через наш ACP-клиент

**Статус:** в работе. Согласовано владельцем, 2026-11-14, чат окна агента («согласовано»); по рекомендации владельца не оспорена — начало с 296.

**Инициатор и разрешение:** владелец, 2026-11-14, чат окна агента (разбор kimi-code): «задачи заведи, как черновики». Предложение показано владельцу в этом чате до создания.

**Проверка дублей:** просмотрены хвост каталога задач (285–295) и база 095-acp-client. 095 — наш ACP-клиент и его база, но второй источник агента там не открывался; задач про подключение стороннего ACP-сервера нет.

**Цель:** проверить, что Канопус может работать со вторым агент-бэкендом — `kimi acp` (MoonshotAI/kimi-code, MIT) — через существующий ACP-клиент `src/acp` (задача 095), не меняя слой продукта.

**Почему это не велосипед:** kimi-code содержит эталонную реализацию серверной стороны ACP (`packages/acp-server`, запуск `kimi acp`); наш клиент по умолчанию говорит с `opencode acp`, источник агента — настраиваемый. Подсматриваем их поток сообщений и обработку углов вместо опытов вслепую.

**Шаги:**
1. Подключить `kimi acp` к `src/acp` как второй источник агента (конфигурация, без правок ядра клиента).
2. Прогнать инициализацию, session/new и один ход; сверить проекцию «ACP → событие движка → событие страницы» на их потоке.
3. Зафиксировать расхождения протокола (частичные ответы, permission-запросы, режимы) и что из `packages/acp-server` берём как эталон для тестов `src/acp_live`.

**Результат:** отчёт о совместимости в этой папке; решение владельца — брать ли kimi-code вторым агентом; при положительном решении — точечные тесты в `src/acp_live` (отдельной работой).

**Приёмка:** владелец по отчёту и демо-ходу в живом продукте.

**Опора:** репозиторий https://github.com/MoonshotAI/kimi-code (docs/en/reference/kimi-acp.md, packages/acp-server); локальный клон для чтения был в `%TEMP%\kimi-readonly` (может быть удалён — восстановить shallow-клоном).
