## Что нужно

1. Исправить подтверждённое смешение баз объектов при snapshot/precheck/merge: документы задачи сверять в управляющем репозитории по его frozen SHA, а result candidate — в привязанном target-репозитории по отдельному SHA. Сохранить связь обоих снимков без подмены source/target. Воспроизведение: задача nova-opencode 146, результат nova-alula ee8f9cad6a92306f33d80bb674784cf0f53ac336, управляющий snapshot 16728a068. core.ts:3747 передаёт result candidate в shared-task-snapshot.ts:77, где его ищут в управляющем repo. Все четыре live docs совпали с управляющим snapshot; result commit отсутствует в его базе объектов. Подготовить узкое исправление в собственном worktree Canopus от origin/main, не менять живую main.

## Критерии приёмки

1. Исполняемый RED воспроизводит ошибку на двух независимых Git-репозиториях, GREEN доказывает правильное сравнение двух frozen SHA. 2. Истинное изменение включённых документов после freeze по-прежнему блокирует merge; отсутствие/несовпадение source snapshot и target candidate не проходит молча. 3. Foreign candidate не вызывает ложный stale при неизменных docs; нельзя заменить source SHA target SHA или наоборот. 4. Сценарий одного repo не регрессирует; служебные state/watch/snapshot/tests-run исключены как прежде; lock и stale guards сохранены. 5. Затронутые tests RED/GREEN, затем полный набор плагина включая pretest и стражи через очередь машины; упавшие параллельно перепроверить отдельно. 6. Signed exact SHA, независимая приёмка и отчёт с проверенными доказательствами; после принятия указать точный путь активации плагина и условия безопасного нового precheck/merge 146. Активация live отдельно по слову владельца.
