## Шаги

1. Инвентаризировать все production entrypoints создания и отмены: plugin, MCP, CLI, автоматические подзадачи. Повторный запуск сессии уже утверждённой задачи не является созданием новой задачи.
2. Реализовать долговечное предложение операции с точной корреляцией содержания и native owner-формы. До подтверждения нет записи задачи, номера, папки, дерева и исполнителя. Модельные owner_words, confirmed:true и переписанный form_id не являются доказательством.
3. Для создания агентом обязательны причина, проверенные существующие задачи и объяснение невозможности работы в их рамках. Показать название, цель и найденные дубли. Отказ/закрытие формы ничего не создают. Одно подтверждение создаёт не более одной задачи.
4. Перед отменой показать task/state/остановки, инициатора, обязательную причину и замену либо объяснённое отсутствие замены. Только подтверждение владельца разрешает продолжение; изменение содержания обесценивает прежнее подтверждение. В истории отдельно хранить инициатора и подтверждение.
5. После подтверждения закрыть native вопросы и связанные ожидания, проверить закрытие, затем отменить. Неизвестный исход/ошибка блокирует terminal cancel и остаётся видимой для безопасного повтора. Существующие отменённые задачи с вопросами обрабатываются без стирания истории.
6. Добавить paused с реальным stop, resume того же номера и owner-confirmed reopening отменённой задачи. Backlog — очередь, paused — временная остановка; состояния припаркованы, но не terminal. Не проигрывать старую работу/приёмку и не снимать HOLD. Перед отменой сохранить reachable контекст; отсутствующая ветка не заменяется default branch. ## Приёмка

Ни один поддерживаемый путь не создаёт и не отменяет задачу без owner approval. До разрешения отсутствуют побочные ресурсы задачи. Подтверждение привязано к точному предложению и применяется один раз. При отмене открытых native вопросов не остаётся, ошибки не выдаются за успех. Данные, история и утверждённые сессии сохранены.
