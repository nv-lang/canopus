## Что нужно

1. Перед созданием новой задачи получить native-подтверждение владельца. Агент обязан указать причину создания, номера проверенных существующих задач и объяснение, почему их недостаточно; сервер добавляет поиск возможных дублей.
2. До ответа не создавать задачу, номер, папку, дерево и исполнителя. Отказ/закрытие формы ничего не создают; повтор не дублирует ресурсы. Запуск следующей сессии существующей задачи не является созданием новой задачи.
3. Перед отменой показать инициатора, обязательную причину, замену либо пояснённое отсутствие замены, текущий статус и остановки. Только native-решение владельца разрешает отмену. Инициатор и подтвердивший записываются отдельно.
4. После подтверждения закрыть native-вопросы и ожидания, остановить исполнение и связанные команды, проверить idle. Лишь затем отменять задачу; неизвестный исход сохраняется для безопасного повтора. Старые отменённые задачи с вопросами диагностируются и исправляются по отдельному подтверждению, без переписывания истории.
5. Реализовать отдельную реальную паузу paused, продолжение resume того же номера и reopening ошибочно отменённой задачи. Пауза/продолжение owner-stop и reopening подтверждаются владельцем, сохраняют причины, прежнее состояние и историю. Backlog означает очередь; он не заменяет остановку работающего исполнителя.
6. Resume/reopen возвращают существующую задачу в безопасное idle без проигрывания прошлой работы/приёмки и без снятия HOLD. Отмена сохраняет reachable контекст невлитых коммитов и рабочее дерево. Отсутствующая ветка требует безопасного восстановления, а не дублирующей задачи или старта от default branch.
7. Одинаково защитить plugin/MCP, внешний CLI, принятие существующей папки без записи, межпроектный заказ и автоматические шаги плана. Все подтверждения привязаны к точному содержанию и действующему родительскому контексту.

## Критерии приёмки

- Ни один production entrypoint не создаёт/отменяет задачу без native owner approval; текст агента и confirmed:true не являются разрешением.
- Показаны rationale и реальные backend-кандидаты; изменённый запрос и новые возможные дубли требуют новой проверки решения.
- Отказ, закрытие, replay, конкуренция и аварийное завершение процесса не создают лишних номеров/ресурсов.
- Ошибка закрытия вопроса или неподтверждённый stop не выдаётся за завершённую отмену/паузу. Одновременные разные действия одной задачи сериализованы.
- Paused не выполняется и не будится watchdog, не занимает execution slot и не является done. Resume/reopen сохраняют номер, отмену в истории, HOLD и контекст; новая задача для продолжения не создаётся.
- Один owner-click в OpenCode завершает операцию через backend; CLI использует явный тот же native протокол.
