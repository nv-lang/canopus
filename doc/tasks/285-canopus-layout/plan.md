## Цель и границы

Единый пользовательский корень по умолчанию — `<home>/.canopus`, с явным разделением независимых продуктов. Общий каталог не означает общий формат конфигурации или базы. Приложение должно работать без плагина, плагин — без приложения и PostgreSQL. Никакой зависимости от внутренней структуры данных другого продукта. Общий протокол или общее хранилище вводить только отдельным явным решением, не в этой задаче.

Согласованная целевая раскладка:

```text
<home>/.canopus/
  config.json               # приложение: настройки приложения
  secrets.json              # приложение: секреты, вне git
  roles.json
  modes/
  presets/
  prompts/
  data/                     # приложение: проекты, сессии и файлы
  state/                    # приложение: журналы и PID
  cache/                    # приложение: каталог агентов и производные данные
  tools/                    # приложения: управляемые внешние инструменты
  backups/                  # перенос и PostgreSQL
  plugin/
    config.json             # глобальные настройки только плагина
    data/                   # карточки, письма, задачи, очередь, маршрутизация
    state/                  # диагностика и журнал смены веток
    cache/                  # снимок каталога моделей
```

Это целевая схема, ещё не реализованная поддержка. Реестр подключения плагина остаётся в конфиге OpenCode; настройки самого плагина переносятся из `.opencode/canopus.json` в `.canopus/plugin/config.json`. Опции регистрации OpenCode после переноса не становятся параллельным источником тех же настроек. MCP и плагин используют один собственный resolver и одну версию схемы данных; приложение их данные не читает. Переменная корня, если общая, определяет лишь расположение, а не совместимость схем.

## Уровни конфигурации и перекрытие

Согласовано владельцем 2026-11-06 в чате: «с остальным согласен, обнови задачу». Порядок ниже — от самого низкого до самого высокого приоритета. Для одного и того же параметра каждый следующий уровень ПЕРЕКРЫВАЕТ предыдущие; отсутствующий параметр наследуется из более низкого уровня.

| Приоритет | Приложение | Плагин |
|---|---|---|
| 1 — самый низкий | Значения по умолчанию в коде | Значения по умолчанию в коде |
| 2 | `<home>/.canopus/config.json` | `<home>/.canopus/plugin/config.json` |
| 3 | `<repo>/.canopus/config.json` | `<repo>/.canopus/plugin/config.json` |
| 4 | `<repo>/.canopus/local.json` | `<repo>/.canopus/plugin/local.json` |
| 5 | Поддерживаемые переменные окружения процесса | Поддерживаемые переменные окружения процесса |
| 6 — самый высокий | Явно заданные аргументы запуска | Явно заданные параметры запуска, если интерфейс их предоставляет; CLI приложения не управляет плагином |

Пример приложения: глобальный `port=8099`, проектный `port=8100`, личный `port=8101`, переменная `CANOPUS_SERVER_PORT=8102`, аргумент `--set port=8103` дают итог `8103`. Без аргумента получится `8102`, без аргумента и переменной — `8101`. Имена действующих env и флагов сверить с кодом при реализации; пример задаёт семантику приоритета.

Личные проектные конфиги исключены из Git. Проектные конфиги содержат только необходимые переопределения. Форматы приложения и плагина независимы. Объекты сливаются по ключам; массивы заменяются целиком, а не неявно склеиваются; явные false, 0 и пустые значения не считаются отсутствующими, если допустимы схемой. Недопустимое значение даёт диагностическую ошибку с источником, а не молчаливое возвращение к нижнему уровню.

Секреты приложения — `<home>/.canopus/secrets.json`, вне Git; обычные конфиги не должны содержать секретных значений. Этот файл служит отдельным источником только разрешённых секретных ключей поверх обычных файлов; переменные окружения и явные аргументы имеют приоритет над ним. Значения скрыты в диагностике. Секреты провайдеров OpenCode остаются в хранилище OpenCode, в Canopus их не копировать. Переменные выбора корня читаются до поиска конфигов; не смешивать выбор каталога с перекрытием параметров.

Проверки: для каждой части проверить наследование отсутствующих ключей, каждый соседний уровень перекрытия, env поверх всех файлов, аргументы поверх env, изоляцию настроек приложения и плагина, отсутствие секретов в диагностике и игнорирование личных файлов Git.

## Что установлено

- Приложение: фронт и хаб, браузерный интерфейс, ACP-агенты, проекты и сессии; хранилище — файлы либо PostgreSQL. PostgreSQL хранит состояние и журнал диалогов приложения, не карточки плагина. Не переносить данные PostgreSQL в файловое хранилище неявно и не удалять том при переносе каталогов.
- Плагин: координация окон OpenCode, роли, задачи, письма, профили и диагностика. Сейчас корень вычисляется внутри каталога данных OpenCode; изменить код и перенести состояние согласованно, включая MCP.
- `projects.json` плагина — опубликованные настройки проектов для MCP, а не список проектов приложения. `doctor.json` — отчёт самопроверки. `model-catalog.json` — производный снимок моделей. `branch-journal.jsonl` — журнал смены ветки и каталога. Одноимённые файлы двух продуктов не объединять.
- `crew-panel-live`: отдельная развёрнутая копия, содержит `doc`, `machines`, `src`, `target` и старые бинарники. До удаления выяснить ссылки запуска и наличие уникальных файлов.
- `crew-tools`: содержит `whisper/bin`, `whisper/models`, загрузочный `_dl`, образец аудио и журналы. Нужные установки перенести в tools, загрузки и журналы классифицировать отдельно.
- `.env` не вводится как обязательный дополнительный конфиг: обычные настройки в JSON, секреты отдельно, переменные процесса поддерживаются. Поддержку проектного dotenv для окружения ACP-агентов сохранить: это другая функция. Автоматического чтения любого `.env` не добавлять.
