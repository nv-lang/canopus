## Критерии приёмки

1. Есть воспроизводимый отчёт с исходным SHA/fixture/точной формулой/размерами выборок/порядком измерений и сырыми данными; baseline и candidate сравнимы, warm/cold/parse/plain read определены. Причина отделена от предположений; если CPU/load не измерены, так и сказано. Никаких утверждений о реальной Nova/Kimi или GitHub CI по synthetic данным.
2. Минимальное исправление имеет причинные RED→GREEN/negative controls: исходный проблемный сценарий воспроизводится или доказан методологический дефект, исправление стабилизирует проверку; намеренное измеримое ухудшение scanner/parse/cache по-прежнему отклоняется. Не просто поднять 4x/6x, убрать assertion, увеличить timeout/retry-until-PASS, снять failing test из npm test или назвать flaky тест GREEN. Если нужна замена критерия, доказать эквивалентную/лучшую защиту исходного perf-контракта и получить отдельное решение при ослаблении.
3. Устойчивость подтверждена не единичным PASS: заранее зафиксированный последовательный план не менее 10 прогонов проблемного файла через очередь, с raw results/failure rate; минимум 3 различающие пробы (позитив/настоящая деградация/пограничные или неблагоприятные условия). Нет молчаливого пропуска красных запусков; доказательство не основано на выборе лучшего результата.
4. Функциональная семантика журналов/cache/scanner, PARSE_BUDGET, отсутствие лишнего процесса/чтения между walks и безопасность путей не регрессируют. Temporary fixtures изолированы, child CREW_* не загрязняет роли теста, Unicode/short path корректно учитываются; production ownership/identity не ослабляются. Scope 136/140/145 не чинить скрыто.
5. Полный набор opencode-plugin/npm test и guards именно новой задачи через очередь, signed exact SHA, независимая приёмка и свежий линейный candidate CI/precheck. Старый красный набор 136/140 не перекрашивать и не мутировать их precheck. Запрет владельца full rerun 140 не отменяется: новый полный набор ЭТОЙ задачи не является новым запуском 140 и не доказывает готовность её code SHA.
6. README/комментарии perf-контракта/тесты согласованы с фактической формулой и trust boundary. Итог ясно говорит, что исправлено/какая защита осталась/какие проверки не проводились. Live/main copy/runtime/config ОС/провайдеры не менялись; дальнейшее применение 136/140 требует их собственного принятого exact-SHA gate и отдельного разрешения где оно необходимо.
