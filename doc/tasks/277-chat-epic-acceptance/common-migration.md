# 277. Проверяемая карта совместимости настроек

## Что эта карта устанавливает

Это часть REQ-23 нового общего кандидата, а не объявление выполненной миграции владельца. Живые настройки, выбранный набор, учётные данные и прежние окна не читаются в публичный отчёт и не изменяются. Источники: `scripts/convert-model-presets.py`, его tests и `doc/tasks/269-agent-pools/conversion.md` в сборочной базе. Новые full checks будут привязаны к immutable общему SHA отдельно; старые восемь положительных tests не выдаются за новый прогон.

| Исходное понятие | Новый runtime / результат плана | Обязательная граница |
|---|---|---|
| `model_profiles` / прежний alias `profiles` | Исходные provider/model/variant сохраняются в migration metadata и чистом плане | Конфликт aliases блокирует весь пакет; произвольные поля/credentials не копируются |
| `profile_sets.<name>` | Один пресет с назначениями ролей | Допустимые имена, известные stage/cell keys, отсутствие частичной активации |
| `develop`, `develop_accept` | `dev`, `dev_accept` | Семья, native model и effort сопоставляются явно по ACP mapping, не угадываются |
| Старое `accept` | Alias `develop_accept`; canonical key имеет приоритет | Shadowed alias с неизвестными/секретными полями всё равно блокирует пакет |
| `plan`, `plan_accept`, `spec`, `spec_accept` | Соответствующие назначения; spec наследует plan при отсутствии явного значения | Наследование фиксируется в metadata, не теряется при переносе |
| `delivery`, `delivery_accept` | Явное назначение либо наследование develop на ступень ниже | Снижение применяют до прежних tier bounds; оно не является model effort |
| `tier: task` | `default` + явные `by_weight.light/medium/heavy` | Для default требуется отдельный явный default weight; вес не подменяет pool level/native effort |
| `tier_min`, `tier_max` | Legacy выбор профиля ограничивается после наследования | Неизвестные/inverted bounds блокируют перенос |
| `profile_set` | `was_active` и сохранённое legacy имя | Это сохранение намерения, не активация новых настроек |
| `provider/model#variant` и отдельный `variant` | Только exact explicit ACP mapping → `{family,model,effort}` | Конфликт вариантов, duplicate mapping или отсутствие строки соответствия — unresolved |
| Старые Nova `roles` пресеты | Не являются входом legacy converter; сохраняются отдельно | Пустой вывод конвертера не считается миграцией этих файлов |
| `context`, `input`, `output` | Сохраняются как исходные значения в чистом плане | **UNRESOLVED в converter**: эквивалентное применение новым runtime не доказано, активируемые файлы не создаются; связь с REQ-23 указана ниже |
| Сообщения/контекст после повторного открытия и restart | Сохраняются journal/session store и фактическим replay | Обязательные REQ-21 и REQ-22; metadata converter не доказывает сохранение истории |
| Новые pools и уровни | Явная схема direct source / `{pool,level}` | Legacy tier не превращается в pool level автоматически |

## План проверки на окончательном общем SHA

1. Полный `src/config` проверяет совместимость новых пресетов и старого прямого role pick; полный ACP/source/live набор — фактическое подтверждение model/effort до prompt и восстановление после restart.
2. Lane `migration` нового `verify-common.ps1` выполняет все converter tests: pure mapping/alias/inheritance/bounds, неизвестные поля, окна, ambiguity/duplicate JSON, побайтное сохранение source, dry-run без записи и отказ повторного/существующего destination.
3. Используются только синтетические исходные настройки и отдельный новый каталог. Флаги записи не применяются к данным владельца, личная активация не выполняется.
4. Даже полный PASS этих tests не доказывает применение token limits `context/input/output`; это конкретный converter/runtime остаток в рамках сохранности настроек REQ-23. Сохранение существующей истории проверяется отдельно по REQ-21/22, а не объявляется отсутствующим из-за отсутствия hot migration.

## Привязка ограничений к исходному требованию

- **Настройки/пресеты:** REQ-23 прямо требует миграции настроек; исходное O-01 владельца от 2026-10-31 требует одного понятия «пресет» вместо профилей и наборов. Минимальный совместимый результат: старый source не переписывается и побайтно сохраняется, известные назначения/aliases/наследование не теряются, explicit mapping не угадывается, любой неэквивалентный параметр выявлен до активации. Данные metadata не доказывают эквивалентный runtime. Token limits являются конкретным неразрешённым входом converter, а не новым требованием поддержать произвольные OpenCode API.
- **История/контекст:** REQ-21 и O-17/O-18 требуют сохранности группы, сообщений и контекста при открытии/restart, в том числе без проекта. REQ-22 сохраняет действующий поток истории/вопросов/отмен. Это обязательно и проверяется настоящим front/hub/journal replay.
- **Direct/pool и усилия:** REQ-01..04, O-01/O-02; native effort, task weight и pool level не смешиваются. O-02 называет более умную стратегию выбора по оставшимся лимитам перспективой. При этом позднее переданное [O-23](../268-chat-agents-epic/task/owner-words.md) прямо упоминает исчерпание лимитов/смену семьи: источник сохранён, такое пожелание не отменено этим минимальным планом миграции.

**Не входят в новые блокеры редизайна без отдельного источника:** hot migration уже открытого модельного окна, автоматический перенос полной истории в другую семью, автоматический quota fallback и полная OS sandbox. В исходных REQ/O-01..O-22 нет требования реализовать такие механизмы ради сдачи этого интерфейса. Их прежние наблюдения остаются отдельно в историческом аудите, но не превращают отсутствие новых возможностей в потерю уже существующей истории. Минимальный достаточный остаток настройки/сохранности согласовывается с исполнителем 269; эта карта не добавляет ему новые обязательства.

Отдельная существенная граница: O-23 существует и не подменяется первоначальным O-02. Пожелание обработки лимита/смены семьи имеет источник; готовый минимальный converter не доказывает соответствующий runtime. Из O-23 не следует право угадывать quota по любой ошибке, автоматически переносить историю или повторять неопределённый dispatch. Точный незакрытый quota/dispatch контракт отражается отдельно в общем результате; его отсутствие не задерживает совмещение независимых готовых интерфейсных delta. Эта карта не объявляет позднее слово отменённым и не самоназначает новую реализацию сверх текущих поручений.

Исполнитель 269 подтвердил этот минимум письмом 2026-11-01 18:26. Точные несовместимые входы converter: любой `context/input/output`; `tier: task` без explicit default weight; отсутствующее/duplicate/ambiguous ACP mapping; неразрешённый `spawn_models`; неизвестные profile fields; неоднозначные aliases. Это fail-closed rejection, не silent loss и не доказательство переноса token windows. Исторические восемь Python tests остаются историческими до нового общего прогона. Новая миграционная работа этим согласованием не назначалась; F-02 исполняется отдельно.

## Связь с общим результатом

Можно сдать безопасный изолированный кандидат с точным перечнем фактически неэквивалентных входов, не активируя потерю параметров. Нельзя заявлять полную эквивалентную миграцию на основании одного metadata. При этом неотнесённые будущие возможности не замораживают весь редизайн. Решение об активации/обновлении живого экземпляра не следует из изготовления кандидата. Проверка адреса 8100 остаётся отдельным разрешённым действием.
