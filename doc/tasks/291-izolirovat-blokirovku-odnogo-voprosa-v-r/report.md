# Отчёт 291

## Результат

Реализация: `36a4444c006cdb5e18204effb366056ab14d8e38`, Signed-off-by.
Последующая правка касается только шапки `plan.md` и этого отчёта;
исходники плагина и тесты после указанного SHA не менялись.

`QuestionLockedError` возникает только при `EEXIST` реально существующего
lock-каталога. `tick` изолирует только этот тип с id текущей записи и возвращает
`locked`/`problems`; остальные ошибки не превращаются в локальный успех.
Файл вместо каталога остаётся ошибкой. `problems()` показывает сохранённый lock
после рестарта без изменения записи/lock/blocker. Сообщение не утверждает,
что доставки не было: lock может возникнуть после уже выполненного I/O.

Fixtures проверяют первый исторический lock, два проекта, актуальный маршрут
с epoch, независимый проверенный native-ответ, mail-outbox, owner/unknown/HOLD,
повтор/рестарт/конкуренцию, неизменность исторических JSON и lock, отказ после
native POST без второй попытки, ошибки схемы и транспорта.

## Проверки и ограничения доказательства

- RED до исправления: целевой тест прерывался на первом lock, exit 1.
- Ранний целевой GREEN: 23 сценария, exit 0; после дополнительной матрицы —
  24 сценария, exit 0, в том числе на чистом SHA реализации.
- Полный `stable --all --runs 1 --jobs 4` на чистом SHA реализации:
  **179/183 GREEN, четыре RED, exit 1**. Все question/pretest прошли.
- Manifest: `pretest` 27 команд, `test` 158, `posttest` отсутствует.
  После исключения отдельно выполняемого cleanup и дубля question-lifecycle
  ожидается 183 уникальных файла; выбранные 183 совпадают, пропусков нет.
- Обязательная одиночная перепроверка четырёх файлов на том же чистом SHA:
  panel-busy, no-queue-behind-question и nudge-matrix — exit 0;
  push-reviewer — снова exit 1 (обнуление counters/stuck).
- Ограниченное сравнение только push-reviewer: архив исходной базы
  `d1c17ea907f8a84e612cd39cc686270bf3a9649a` — 1/1 exit 0;
  архив кандидата — 2/2 exit 0; затем worktree кандидата — 2/2 exit 0.
  В последних проверках worktree имел только незакоммиченную правку шапки
  плана; этот факт записан в raw. Это **не** доказательство полного GREEN
  и **не** установленная причина прежних падений или baseline defect.
- Первые стражи не увидели untracked plan. После коммита проверка честно
  дала RED за его шапку. Шапка исправлена; финальные стражи и exact-SHA
  целевой прогон выполняются отдельно от прежних результатов.

**Blocker сдачи:** полного GREEN нет; причина нестабильности push-reviewer
не установлена. По рабочему указанию интегратора новые full/бесконечные повторы
не выполняются; counters/fixtures ради GREEN не правились. Нужна независимая
оценка кода и результатов; финальная приёмка не заявлена.
