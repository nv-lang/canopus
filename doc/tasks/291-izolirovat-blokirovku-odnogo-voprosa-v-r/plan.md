# План 291

Источник: `task/message.md`, решение владельца в нём; live отдельно.

1. Детерминированный fixture: первая по порядку запись с lock-каталогом,
   независимые вопросы двух проектов и готовый проверенный native-ответ.
   Снять RED до изменения реализации.
2. Типизированный отказ только при занятом lock-каталоге (`EEXIST`).
   В `tick` перехватывать только этот тип и только для обрабатываемого id;
   остальные ошибки сохраняют прежний отказ. Возвращать локальные отказы,
   показывать существующие lock в `problems()` без записи runtime-состояния.
3. Проверить повтор, рестарт, конкуренцию, неизменность исторической записи,
   blocker и lock; отрицательные проверки других ошибок. Через очередь
   прогнать затронутые тесты, полный плагин (включая pretest), стражи.
4. Подписанный коммит с точным SHA и отчёт с raw; независимая приёмка
   интегратором. Не применять в main/live и не перезапускать сервис.

Безопасная активация существующего вопроса: после отдельно разрешённого
обновления принятым кодом дать штатному `tick` обработать сохранённую запись;
не создавать qid и не назначать epoch вручную. Истёкший deadline не обходить:
такой вопрос проходит существующий blocker-путь, а не получает новые полномочия.
