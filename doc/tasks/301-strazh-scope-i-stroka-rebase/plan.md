**Статус:** черновик (создан по слову владельца; до подтверждения в приложении номера и папка условные). Дополнен 2026-11-14 итогами задачи 300 (И1–И3) тем же словом владельца («по рекомендации»).

**Проверка дублей:** хвост каталога задач и черновики 296–300 — стражей scope нет; правило о ребейзе после приёмки в Каноне не записано; словарь исходов стражей и правило слоёв не записаны (299 дал карту событий без исходов).

## Что нужно

1. **П1 — страж scope.** На воротах слияния (pre-push/pre-commit — решается при реализации) проверять: diff ветки задачи против её базы лежит в файлах, заявленных в «Пересекается (файлы)» её `task/message.md`, плюс файлы её собственной папки задачи. Нарушение — исход «спросить владельца» (не блок молча). Образцы: мердж-проверка Tower (297); whitelist опасных команд ZCode с правилом «нераспознанное ≠ безопасное» (`docs/dangerous-command-approval-v1-plan.md`).
2. **П2 — строка в `doc/canon/process.md`:** после приёмки сдвиг базы (ребейз на новый `main`) требует перепрогона тестов, но не новой приёмки, если diff изменился только разрешением конфликтов ребейза.
3. **И1 — словарь исходов стражей:** в `doc/canon/guards.md` (задача 299) добавить колонку «исход»: **блокирует / спросить владельца / наблюдает**; зафиксировать «спросить владельца = вопрос с рекомендацией» (форма уже наша). Образцы: Codex `Allow/Prompt/Deny` (`execpolicy/src/policy.rs`); трёхзначные хуки Codex `Success/FailedContinue/FailedAbort`; типизированная карта результатов хуков Claude SDK; аудитория вывода хука (exit 2 — модели, exit 1 — человеку).
4. **И2 — правило слоёв в Канон:** вышележащая настройка (проектный файл) не включает/не выключает стражи нижележащей (глобальный файл, константы кода); изменение конфигурации хуков не задевает идущие сессии (доверие по дайджесту, ZCode `docs/workspace-hook-trust-*.md`). Ключи стражей в `.canopus/plugin/config.json` сверить с этим правилом.
5. **И3 — строка в Канон:** внешний эффект — только после durable записи в журнал; прерванное действие получает «исход неизвестен» и не авто-повторяется (dsh `session-checkpoint-policy`; ZCode — нераспознанный ввод при перезапуске явно `discarded`).
