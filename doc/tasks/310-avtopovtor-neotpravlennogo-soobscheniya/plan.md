# 310. Автоповтор неотправленного сообщения и повтор с вложениями

**Инициатор и разрешение:** владелец, 2026-11-15, чат интегратора: «очень часто такое бывает, возможно нужно пытаться отправить повторно несколько раз автоматически и добавить кнопку отправить повторно, включая прикрепленные файлы (картинки)?»; завод задачи — «по рекомендации».

**Фон:** 2026-11-15 сообщение с картинкой в сессии «Интегратор» дважды не отправлено после перезапуска сервиса (сокет страницы ещё не восстановился, индикатор показывал «Подключено»); дошло только по ручному «Отправить сейчас». Повторяющийся разовый сбой — ручной ретрай не лечение.

## Суть

Повтор отправки на странице есть, но с двумя дырами:

1. **Картинки запрещены:** `src/web/delivery.js:74` — `canRetry` возвращает false при `images.length > 0`, кнопка ↻ не работает для сообщений с вложениями. При этом очередь (`src/web/queue.js`) хранит картинки и пересылает их при выдаче — запрет на повтор выглядит перестраховкой.
2. **Автоповтора нет:** при транспортном отказе (`transport.send` вернул false → причина «offline») сообщение помечается «Не отправлено» и ждёт ручного клика.

## Что нужно

1. **Повтор с вложениями:** ↻ работает и для сообщений с картинками — при повторе заново выполняется `uploadImages` (путь `postImage`, байты через `/api/session-image/<trace>`), затем обычная отправка. Не повторять загрузку для уже загруженных (`n` сохранён) — иначе двойные копии.
2. **Автоповтор транспортных отказов:** причина «offline» (сокет закрыт, `conn.send_failed`) → автоматические попытки с паузами по ступеням сокета 2/5/10 с (`RETRY_STEPS`, `src/web/transport.js`), максимум 3 попытки; каждая отражается в карточке («попытка N…»). Приёмы исчерпаны → состояние «Не отправлено», кнопки ручного повтора остаются.
3. **Не автоповторять содержательные отказы** (ошибка сервера, отказ агента, лимит, «Дождитесь завершения переноса») — у них остаётся только ручной повтор.
4. **Совместимость с 039:** после исчерпания попыток «вернуть в поле ввода» работает как в задаче 039; дублирование сообщения исключается существующей страховкой `sentAt` в `queue.js` и квитанциями `message_delivery` (задача 260 — повтор с тем же `client_id` сервер отвечает известной квитанцией, дубля не будет).

## Критерии приёмки

- `npm test` в `src/web` зелёные; новые тесты: (а) повтор сообщения с картинкой — загрузка вызывается один раз, отправка уходит; (б) при «offline» — 3 автопопытки с паузами, затем «Не отправлено»; (в) содержательный отказ автоповтора не запускает; (г) повтор при уже известном `client_id` не создаёт дубль в ленте.
- Проба руками: разорвать сокет (перезапуск сервиса) при набранном сообщении с картинкой → после возврата сокета сообщение уходит само.
