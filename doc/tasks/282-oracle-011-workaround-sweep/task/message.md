# Задание: снятие меток ORACLE-WORKAROUND, починенных в Nova Oracle 0.1.1

Дата задания: 2026-11-03. Источник: поручение волны снятия меток (оркестратор, 2026-11-03);
тулчейн 0.1.1 выпущен (тег oracle-v0.1.1, коммит 31c8f6041).

## Что нужно

По инструкции шапки `spikes/env/workarounds.md`: открыть места с метками items, починенных
в 0.1.1, упростить код как говорит метка, снять метку; каждый шаг верифицировать сборкой и
тестами юнита тулчейном 0.1.1; в конце `python scripts/oracle-workarounds.py --index`
(страж следит за совпадением). Items к снятию: 10, 12+13 (+26), 25, 30, 32, 33, 36, 47, 51,
52 (если есть), 55. НЕ трогать: 19, 57, 22/31 и прочие незакрытые.

## Критерии приёмки

AC-1. Метки перечисленных items сняты там, где упрощение собирается и проходит тесты на
тулчейне 0.1.1; где 0.1.1 всё ещё ломает C — метка остаётся с обновлённым текстом находки.
AC-2. `python scripts/oracle-workarounds.py --index` перегенерировал `spikes/env/workarounds.md`,
стражи дерева зелёные.
AC-3. Все юниты, где снимались метки, зелёные на 0.1.1 (известный исключённый таймаут
`src/server/agent_config` воспроизводится и на чистом main — не связан со снятием).
AC-4. Найденные новые дефекты 0.1.1 записаны: обновлёнными текстами меток и спайком
`spikes/env/repro_infer12_chat` (вывод типовых аргументов chat-формы: `Nova_ChatState_p`
в сгенерированном C; починен в nova-opencode e5964ec26, в релизе 0.1.1 ещё ломается).
