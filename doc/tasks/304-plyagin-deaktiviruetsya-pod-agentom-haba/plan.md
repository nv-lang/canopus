# 304. Переменная `CANOPUS_AGENT_OF_HUB`: плагин деактивируется под агентом хаба

**Статус:** исполнено, принято, влито (2026-11-15, интегратор: ff-only, локальный `main` HEAD `1225b18b`; `192c2539` + `1225b18b` поверх `dbe7d0e8`). Слово владельца на старт: «по рекомендации», 2026-11-14, чат приёмщика (рекомендация — явный старт 304); передано интегратором исполнителю. Форма сдачи согласована с приёмщиком: ветка от `main` (`dbe7d0e8`), nova-тесты пофайлово (напоминание: `nova test <каталог>` гонит один файл), плагин — полный `npm test` до пуша (до сдачи — затронутые) + `test:stable` для упавших под нагрузкой; коммит → приёмка с diff. Доработка по замечанию приёмки: `refuseLegacyEnv` перенесён до маркер-выхода в обеих точках (`1225b18b`), тест 4а «маркер + CREW_* → throw». Финальная приёмка: существенных 0.

**Прогоны и порог таймаута (2026-11-15):** серверный юнит `canopus_task_test` при текущей нагрузке машины легально живёт дольше 300 с (смерть ровно на границе таймаута: 563 с при 60, ~840 при 300; **PASS с `--timeout 900`** — подтверждено исполнителем и приёмщиком независимо). Рабочее правило этой машины: серверные юниты — `--timeout 900`; в Канон не переносится до отдельного слова владельца.

**Инициатор и разрешение:** владелец, 2026-11-14, чат окна агента — идея владельца дословно: «ставить определенную переменную окружения, на которую реагирует наш плагин под opencode и просто деактивирует себя при наличии этой переменной. Таким образом не нужно править конфиги opencode при его старте и наш плагин, если он установлен в opencode, не будет мешать работе основному продукту»; согласовано («по рекомендации»).

**Проверка дублей:** 192.9/D454 (`src/agent_config.nv`) — уже изолирует агента хаба **вырезкой плагина из копии глобального конфига** (`XDG_CONFIG_HOME` на `<data_dir>/agent-config/xdg`); закрывает только плагины из глобального конфига. Задач на переменную сам-деактивации нет; коллизий имён нет — `refuseLegacyEnv` (284) ловит только `CREW_*`/`OPENCODE_CREW_*` и конкретный список устаревших ключей.

## Суть (два пояса, не замена)

1. **Пояс 1 (существующий, остаётся):** вырезка плагина из копии конфига — принудительная, не зависит от согласия плагина (fail-closed).
2. **Пояс 2 (новое):** переменная `CANOPUS_AGENT_OF_HUB=1` — добровольная сам-деактивация плагина (fail-open), закрывающая то, что вырезка не видит: плагины **проектного уровня** (каталог сессии), плагины из других источников конфигурации, будущие плагинные системы иных ACP-агентов.

## Что нужно

1. **Хаб** (`src/server/hub.nv`, `@agent_env`): добавлять `CANOPUS_AGENT_OF_HUB=1` в окружение **всех** агентов хаба (не только opencode) — поверх переменных проекта; в трассу значения не пишутся (правило 192m).
2. **Плагин** (`opencode-plugin/index.ts`, `setup()`, рядом с `refuseRuntimeEnvironment`): при наличии переменной — регистрировать пустой плагин (без хуков и инструментов) с одной заметкой в собственном журнале плагина «деактивирован: агент хаба»; не ошибкой, а тихой деактивацией.
3. **Тесты**: nova-тест хаба — окружение агента несёт переменную; тест плагина — с переменной `setup()` отдаёт пустую регистрацию, без переменной поведение прежнее.
4. **Зонд-проверка на живом**: старт opencode с переменной → плагин неактивен (нет визитки, нет инструментов плагина).
5. **Документация**: строка в `src/agent_config.nv` (зачем два пояса) и в `opencode-plugin/README.md`.

## Критерии приёмки

- Проба «подсунь негодное»: проект с плагином в каталоге + агент хаба с переменной → плагин неактивен; без переменной → активен.
- Наборы тестов затронутых частей зелёные (`nova test src/server`, `npm test` плагина — по п. 7–9 AGENTS.md).
