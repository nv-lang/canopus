# Карта стражей: событие → страж → блокирует или наблюдает

Часть Канона проекта ([состав Канона](README.md)). Описательная карта, не новая норма: она сводит в одно место то,
что уже записано в [AGENTS.md](../../AGENTS.md) («Стражи», «Git») и в заголовках самих скриптов `scripts/guards/`;
кода карта не меняет. Источник сверки — задача 299 (черновик), 2026-11-14.

Классификация событий, как в карте kimi-code (задача 297): **блокирующее** событие — страж красным отклоняет
команду git; **наблюдательное** — страж находит и печатает, ход работы сам не останавливает. Слой хуков агента —
подсказка: красный не блокирует ничего, судится приёмкой.

## События и стражи

| Событие | Где стоит | Страж | Действие |
|---|---|---|---|
| Коммит (до записи в историю) | хук `pre-commit` | `run-all.sh --index` — все стражи `check-*` по индексу; `guard-secrets.py --index` | **блокирует** коммит |
| Сообщение коммита | хук `commit-msg` | `guard-commit-message.py` (подпись `-s`, язык, трейлеры, номер задачи, приватные данные) | **блокирует** коммит |
| Пуш, по каждому коммиту диапазона | хук `pre-push` | `guard-secrets.py`, `check-private-names.py`, `check-text-hygiene.py`, `guard-commit-message.py` — все с `--commit` | **блокирует** пуш |
| После пуша (CI) | `.github/workflows/guards.yml` | `check-wiring.py`, `guard-commit-message.py`, `guard-secrets.py` — перепроверка того же | **красит** CI; слитие — защита ветки `main` |
| Рабочее дерево целиком (ручной/плановый прогон) | команда, не хук | `run-all.sh` (все `check-*`), `guard-secrets.py --tree` / `--commit <хеш>` | **наблюдает**: находит и печатает |
| Ход и оболочка агента | хук агента плагина (`opencode-plugin/branch-guard.ts` и соседние) | каталог и ветка (`canopus_branch_note`), чужие деревья, служебные границы | **подсказка, не барьер**: отклоняет ход с правилом, обходится внешним терминалом; судится приёмкой |
| Самоход самотестов | команда | `selftest/run-selftests.sh`, `prove-red.sh`, `probe-empty-root.sh` | проверяют самих стражей, к ходу не привязаны |

## Стражи дерева (`check-*`, идут в `pre-commit` через `run-all.sh --index`)

| Страж | Что проверяет |
|---|---|
| `check-md-links.py` | ссылки и якоря в отслеживаемых `.md`: цель существует, внутри репозитория |
| `check-no-legacy-name.py` | прежние имена продукта не встречаются в активных файлах |
| `check-no-status-table.py` | рукописных таблиц статусов задач нет |
| `check-open-questions.py` | форма файла открытых вопросов и пометок разбора; счёт просроченных |
| `check-oracle-workarounds.py` | метки обходов дефектов Oracle ведут к пункту README |
| `check-private-names.py` | имена из списка владельца (`~/.canopus/guards/private-names.txt`; в CI — секрет) не встречаются |
| `check-release-kit.py` | машины, которые хаб читает с диска, согласованы с релизным комплектом |
| `check-task-docs.py` | форматы документов задач: статусы spec/plan, заходы проверок, журнал хода, задания, номера |
| `check-tests-have-checks.py` | файл теста плагина не пустой: хотя бы одна проверка |
| `check-text-hygiene.py` | гигиена текста: управляющие байты, NUL, UTF-16, U+FFFD, BOM, смешанные концы строк |
| `check-wiring.py` | страж стражей: каждый документирован, подключён, проверен самотестом |

`guard-secrets.py` (не `check-*`, поэтому отдельно от `run-all.sh`): секреты и пути машины — индекс, коммит или
дерево; значение нигде не печатается. Список запрещённых имён — вне репозитория, нет списка — страж красный,
а не молчит (AGENTS.md, «Стражи»).

## Границы карты

- Красный git-хука — не барьер насовсем: `--no-verify` обходится, вложенные оболочки хук агента не видит; CI
  перепроверяет то же после пуша, финальный суд — приёмка и владелец на воротах сдачи. Нашёл нарушение —
  исправь текст, а не обходи страж.
- Пометка «механизм» в AGENTS.md стоит только там, где механизм правда есть; эта карта не добавляет механизмов.
- Новый страж попадает сюда тем же коммитом, что подключается (`check-wiring.py` следит), и в задаче-источнике.
