# Каталог задачи

Оркестратор и сессии используют эту конвенцию, чтобы определить состав каталога задачи и место каждого документа.
Конвенция объединяет ссылки на действующие правила Канона.
Форматы документов и порядок сессий задают источники, указанные ниже.

Основание: владелец, 2026-11-28, поручение исполнителю в текущем чате: «поручи написать конвенцию для каталога задачи, если таковой нет сейчас».

## Каталог и имена

Оркестратор создаёт задачу по [правилу жизненного цикла](task-lifecycle.md).
Оркестратор получает номер через механизм из [process.md, «Задача, сессия, подзадача»](process.md#задача-сессия-подзадача).
Оркестратор использует имя `NNN-<slug>/` внутри настроенного `tasks_dir`.
В этом проекте значение по умолчанию — `doc/tasks`.
Оркестратор дополняет номер нулями слева до трёх цифр.
Для номера длиннее трёх цифр оркестратор сохраняет все цифры.
Оркестратор выбирает краткое обозначение цели для `<slug>`.
Канон не задаёт отдельного словаря или языка для `<slug>`.

Сессия сохраняет имена файлов из таблицы состава без перевода.
В имени проверки сессия заменяет `N` номером захода соответствующего цикла.
После обратной связи сессия продолжает нумерацию проверок без перезаписи прежних файлов.
Для `feedback-N.md` оркестратор использует отдельный номер раунда обратной связи.
Правила нумерации задаёт [методика, «Правила»](https://github.com/unitcraft/ai-dev-methodology/blob/744e0af34dc9c7f9d4db2a91e312ee170c6642fd/task-sessions.md#правила).

Оркестратор различает общий каталог активных данных и версионные снимки документов по [configuration.md, «Единое хранилище задач (288)»](configuration.md#единое-хранилище-задач-288).
Исполнитель правит исходный код только в своём рабочем дереве по [AGENTS.md](../../AGENTS.md).

## Состав по маршрутам

Оркестратор определяет маршрут до подготовки документов по [process.md, «Опытные нормы методики»](process.md#опытные-нормы-методики).
Эпик — вид задачи, а не четвёртый маршрут.
Оркестратор задаёт состав эпика по [методике, «Большая работа: эпик»](https://github.com/unitcraft/ai-dev-methodology/blob/744e0af34dc9c7f9d4db2a91e312ee170c6642fd/task-sessions.md#большая-работа-эпик).

В таблице «обязательно» означает наличие файла к завершению указанного этапа.
Сессия не создаёт пустые файлы будущих этапов ради соответствия таблице.
В столбце «Кто пишет» указана роль, ответственная за содержание.
Плагин или хаб может записывать файл от имени этой роли.

|---|---|---|---|---|---|
| `task/message.md` | Оркестратор | Обязательно при подготовке | Обязательно при подготовке | Обязательно при подготовке, малая форма | Обязательно при подготовке |
| Другие материалы `task/` | Оркестратор | При наличии входных материалов | При наличии входных материалов | При наличии входных материалов | При наличии входных материалов |
| `log.md` | Оркестратор | Обязательно с подготовки | Обязательно с подготовки | Обязательно для решений и меток маршрута | Обязательно с подготовки |
| `spec.md` | С1; оркестратор утверждает | Обязательно после разбора | Утверждённая копия постановки по методике | Не требуется | Обязательно, требования цели эпика |
| `spec-trace.md` | С1 | При выносе описи, покрытия или истории | При применении такого выноса | Не требуется | При применении такого выноса |

| `feedback-N.md` | С9 | На каждый разбор обратной связи | На каждый разбор обратной связи | При отдельном назначении разбора | На каждый разбор обратной связи |

Состав артефактов цикла задаёт [методика, «Подготовка»](https://github.com/unitcraft/ai-dev-methodology/blob/744e0af34dc9c7f9d4db2a91e312ee170c6642fd/task-sessions.md#подготовка).
Оркестратор выбирает версию методики для задачи по [process.md, «Версия и переход»](process.md#версия-и-переход).
Ссылки на закреплённую основу в этой конвенции не переводят активные задачи на другую версию.
Оркестратор не кладёт копию `task-algorithm.md` в каталог задачи согласно [отличиям проекта](process.md#отличия).

Для малого маршрута оркестратор использует проектное правило из [process.md, «Опытные нормы методики»](process.md#опытные-нормы-методики).
Для быстрого маршрута оркестратор проверяет [требования методики к постановке](https://github.com/unitcraft/ai-dev-methodology/blob/744e0af34dc9c7f9d4db2a91e312ee170c6642fd/task-sessions.md#правила).
Пропуск этапов оркестратор определяет по принятой версии методики.
Отсутствие файла в свежей карточке задачи само по себе не разрешает пропуск этапа.

Для эпика оркестратор ставит `Тип: эпик` в разделе «План» файла `plan.md`.
В задании дочерней задачи оркестратор ставит первой непустой строкой `Эпик: NNN`.
Форму таблицы детей и связь задач задаёт [process.md, «Дополнения»](process.md#дополнения).
Каждый исполнитель дочерней задачи ведёт собственный каталог по выбранному маршруту.

## Форматы и источники

Оркестратор пишет обычное задание по [образцу `task/message.md`](process.md#задание-taskmessagemd).
Для малого маршрута оркестратор использует малую форму из [правила маршрута](process.md#опытные-нормы-методики).
Образцы свежих задач не заменяют эти правила.

| Документ | Где сессия берёт формат |
|---|---|
| `spec.md`, `spec-trace.md`, `spec-review-N.md` | [Методика: правила и промпты С1, С2](https://github.com/unitcraft/ai-dev-methodology/blob/744e0af34dc9c7f9d4db2a91e312ee170c6642fd/task-sessions.md) |
| `plan.md`, `plan-review-N.md` | [Методика: промпты С3, С4](https://github.com/unitcraft/ai-dev-methodology/blob/744e0af34dc9c7f9d4db2a91e312ee170c6642fd/task-sessions.md) |
| `result.md`, `review-N.md`, `delivery/`, `delivery-review-N.md`, `feedback-N.md` | [Методика: промпты С5–С9](https://github.com/unitcraft/ai-dev-methodology/blob/744e0af34dc9c7f9d4db2a91e312ee170c6642fd/task-sessions.md) |
| `current.md`, строки назначения в `spec.md` и `plan.md` | [Process: «Результат и куда он попадает»](process.md#результат-и-куда-он-попадает) |
| `log.md`, `profile.log`, `usage.log` | [Process: «Дополнения»](process.md#дополнения) |
| `progress.log` | [Process: «Журнал хода» внутри «Дополнений»](process.md#дополнения) |

Оркестратор хранит решения, pin методики и сведения о запусках в `log.md`.
Работающая сессия пишет ход выполнения в `progress.log`.
Исполнитель ведёт доказательства реализации в `result.md`.
При первом переносе документного результата исполнитель создаёт `current.md` по [правилу размещения результата](process.md#результат-и-куда-он-попадает).
Если исполнитель использует дополнительный `progress.md`, он не заменяет этим файлом обязательные документы и журналы.
Канон не задаёт отдельного обязательного формата `progress.md`.

## Что попадает в Git

Оркестратор сохраняет документы задачи как версионные снимки по [контракту общего хранилища](configuration.md#единое-хранилище-задач-288).
Плагин коммитит начальные `task/message.md` и `log.md` на ветке задачи по [правилу создания папки](process.md#задача-сессия-подзадача).
Интегратор переносит документы в `main` на воротах утверждения спецификации, утверждения плана и сдачи по [отличиям проекта](process.md#отличия).
Эти правила не разрешают исполнителю самостоятельно обновлять живую основную копию.

Перед коммитом исполнитель отбирает документы и допустимые входные материалы по [правилам публичности](../../AGENTS.md).
Исполнитель перечисляет файлы в команде коммита по [правилам Git](../../AGENTS.md).
Служебное состояние Canopus остаётся приватным по [configuration.md](configuration.md#единое-хранилище-задач-288).
Исполнитель не включает в коммит runtime-файлы, исключённые [`.gitignore`](../../.gitignore).
Расположение runtime-файла исполнитель определяет по контракту хранилища, а не по устаревшему описанию `task/state.json`.

## Что проверяют стражи

Исполнитель сверяет возможности стража с [`check-task-docs.py`](../../scripts/guards/check-task-docs.py).
Страж проверяет существующие документы по выбранному режиму.
Страж не проверяет комплектность каталога по маршруту.

| Объект | Проверка `check-task-docs.py` |
|---|---|
| Номера каталогов | Отсутствие двух каталогов с одним номером |
| `spec.md`, `plan.md` | Первая строка статуса |
| `spec.md` | Уникальность идентификаторов REQ, AC, DNC в начале строк |
| Файлы проверок | Итоговая первая строка и соответствие номера захода имени файла |
| `spec.md`, `plan.md`, `current.md` | Строки назначения и условия наличия указателя результата для задач после установленной даты |
| `task/message.md` | Заголовок, разделы, заполненность и дата слов владельца для новых задач; отдельная проверка малой формы |
| `progress.log` | Форма строк, пути машины и дополнительные правила журнала с ограничениями по режиму и дате |
| `log.md` | Добавленные датированные строки в индексе; дополнительные правила записей о воротах |
| Связи эпика | Форма таблицы детей, наличие родителя и строки ребёнка при наличии таблицы |

Переходные даты, точные условия и исключения перечисляет описание в начале файла стража.
При проверке дерева или CI страж не проверяет ограничения, которым нужны добавленные строки индекса.
Страж не доказывает дословность слов владельца, полноту требований или честность журнала.
Приёмщик проверяет эти свойства по исходным материалам и артефактам.
Состав остальных стражей исполнитель определяет по [карте стражей](guards.md).
