# Философия Канопуса

## Канопус ведёт задачу

Канопус определяет следующий шаг задачи от постановки до выпуска в рабочую среду. Агент выполняет порученный шаг и возвращает результат. При смене агента или модели Канопус должен применять тот же порядок шагов и те же условия приёмки. [ADR-0018](decisions/ADR-0018-process-in-canopus.md)

## Журнал хранит состояние задачи

Канопус засчитывает выполнение шага по событиям в журнале задачи. После перезапуска или смены агента Канопус должен восстановить по журналу, какие шаги завершены и на каком шаге продолжить работу. [ADR-0018](decisions/ADR-0018-process-in-canopus.md)

## У ожидания есть срок

Когда Канопус ждёт ответа агента, сервера или дочернего процесса, он должен ограничить время ожидания. Если запущенный процесс сам не завершает работу по сроку, Канопус назначает сторожа, который остановит зависший процесс. Если срок ожидания истёк, Канопус должен показать владельцу причину остановки и записать в журнал последнее событие и длительность ожидания. [Правила ожидания](no-silent-waits.md)

## Неизвестный вход получает явный отказ

Если Канопус не распознал входные данные, он должен вернуть отказ с кодом и объяснить причину. Например, если клиент передал неизвестный параметр строки запроса на `/api/*` или `/ws`, сервер должен вернуть статус HTTP 400 и код `invalid_parameter`. [Формат ошибок API](api-deviations.md)

## Автоматизация обходится без дополнительных запросов к модели

Канопус должен отслеживать сроки и отправлять напоминания с помощью таймеров, сторожей и журнала. Когда наступит время продолжить задачу, Канопус должен запустить следующий рабочий ход агента без отдельного запроса к модели для проверки срока. [ADR-0018](decisions/ADR-0018-process-in-canopus.md)

## Команда обращается к владельцу, когда нужно его решение

Если исполнителю нужен факт для работы, он обращается к автору задачи. Если автор недоступен, рабочий вопрос решает интегратор проекта. Когда Канон требует решения владельца, интегратор передаёт ему вопрос с рекомендацией и обоснованием. Команда продолжает работу, для которой требуется это решение, после ответа владельца. [ADR-0017](decisions/ADR-0017-working-questions-through-integrator.md)

## Заимствование идеи можно проверить по источнику

При исследовании другого продукта автор разбора указывает точную версию или ревизию и способ проверки. Если идея решает задачу Канопуса, команда может использовать принцип, контракт или формат данных. Команда пишет реализацию самостоятельно, без копирования кода донора. [Правила исследования сторонних продуктов](../research/README.md)

## Маршрут задачи зависит от объёма и риска

При выборе глубины проверки команда должна учитывать и объём работы, и риск ошибки. Для обратимой правки можно применить малый маршрут, если владелец его выбрал и просмотра результата достаточно для приёмки. Если работа требует нескольких самостоятельных результатов, команда предлагает владельцу эпик с отдельными задачами. [ADR-0013](decisions/ADR-0013-proportionality-ahead-of-pin.md) и [правила выбора маршрута](process.md)
