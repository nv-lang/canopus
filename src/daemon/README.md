# Локальный canopus-daemon

Хаб включает транспорт демона, если в `state/daemon.json` его экземпляра есть `{"port": <порт>}`. Ключ хранится рядом в `state/daemon.key`. Файл ключа должен быть доступен только пользователю, под которым работают демон и хаб.

Демон запускается отдельным процессом `canopus daemon --port <порт> --key-file <путь-к-daemon.key>` и слушает `127.0.0.1`. `--port 0` подходит для проб. Фактический порт печатается при запуске. При заданном адресе ошибка подключения или авторизации возвращается хабу при попытке запуска агента.

Хаб хранит привязку к агенту, состояние разбора ACP и события кадров в inbox сессии. Записи `Link.ack` отмечают события, зафиксированные движком. После перезапуска курсор ставится перед первым кадром с неподтверждёнными событиями. Повтор уже записанного кадра использует сохранённые события с прежними идентификаторами.

Восстановление зависит от живого демона и его окна выдачи. Предел ACP-строки составляет 8 МиБ. Отдельный HTTP MCP-запрос к прежнему процессу хаба может завершиться по разрыву соединения. Нативные формы и разрешения ACP остаются в сохранённом состоянии клиента.

Обе проверки рассчитаны на Linux и используют собранные бинарники.

```sh
python3 src/daemon/local_test.py <canopus>
python3 src/daemon/hub_test.py <canopus> <canopus-hub>
python3 src/daemon/hub_test.py <canopus> <canopus-hub> --restart
python3 src/daemon/hub_test.py <canopus> <canopus-hub> --late-ack
python3 src/daemon/hub_test.py <canopus> <canopus-hub> --graceful
```
