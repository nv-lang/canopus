# Отклонения от конвенции API

Задача 326 (владелец, 2026-11-27). Конвенция — [unitcraft/engineering-conventions, api.md](https://github.com/unitcraft/engineering-conventions/blob/main/api.md) (редакция 1.1). Её §19 требует: отклонение от правила допустимо, если оно записано — правило, что сделано иначе, почему, цена и условие снятия. Эта страница и есть такая запись для HTTP/WebSocket API сервера Canopus (`src/server/front/`, протокол — [src/server/README.md](../../src/server/README.md)).

Модель, из которой следует большинство строк: сервис слушает только loopback (`127.0.0.1`), у него ровно один клиент — страница пульта из того же артефакта, и один пользователь — владелец машины. Внешних потребителей API нет и не планируется.

| Правило конвенции | Сделано иначе | Почему | Цена | Условие снятия |
|---|---|---|---|---|
| Версия API в пути или заголовке | Версии нет: ни `/v1/`, ни заголовка | Один артефакт: клиент (страница) и сервер собираются и обновляются вместе, рассинхрон версий невозможен | Внешний клиент не сможет закрепить совместимую версию | Появление второго, независимо обновляемого клиента |
| TLS и токен на API | Loopback без TLS и без токена; защита — проверкой `Origin` (чужой → 403) | Локальная модель доверия ([src/server/README.md](../../src/server/README.md)): браузер — единственный источник чужих запросов к loopback, `Origin` их отсекает; изоляции от произвольного процесса под той же учётной записью нет и не заявлена | Любой локальный процесс может звать API; вынос порта наружу мгновенно открывает всё | Прослушивание не-loopback адреса или доступ с другой машины — до этого обязательны TLS и токен |
| Ошибки — RFC 9457 (`application/problem+json`) | Свой формат `{"error", "code"}`: человеческий текст и машинный код snake_case из закрытого набора | Один клиент со своей страницей разбора ошибок; problem+json не даёт ему ничего, а тип медиа и поля пришлось бы тащить через все обработчики | Инструменты, понимающие RFC 9457, формат не распознают | Внешний потребитель API или требование конвенции к публичным API проекта |
| Время — ISO 8601 (`Z`) | Epoch-миллисекунды числом (`t`, `at`, `observed_at`, …) | Числа дешевле в разборе и сравнении в обеих сторонах; формат читают только машины, страница сама форматирует для человека | Поле времени нельзя прочесть глазами в сыром JSON | Публикация API наружу или хранение, где сырой JSON читают люди |
| `X-Request-Id`, `ETag`, `Retry-After`, идемпотентность мутаций, `If-Match` | Нет ни одного | Один пользователь, один клиент без очередей и повторов; конкуренция правок невозможна по построению; трассировка — локальным журналом сервера | Повтор запроса клиентом не защищён от двойного эффекта; рассинхрон версий ресурса не отличить | Очереди повторов в клиенте, несколько вкладок/пользователей, внешние клиенты |
| Пагинация коллекций (`limit`/`cursor`) | Нет; вместо неё жёсткие пределы в коде (`truncated`, обрезка по байтам/строкам) | Списки малые и локальные (проекты, сессии, папки); предел зафиксирован рядом с кодом и виден клиенту флагом `truncated` | Коллекция больше предела молча недоступна целиком | Рост реальных списков за пределы или внешний потребитель |
| Контракт — OpenAPI-схема с линтером в CI | Контракт — проза [src/server/README.md](../../src/server/README.md) плюс тесты маршрутов | Один клиент в том же репозитории; схема дублировала бы README и тесты, линтер — ещё один инструментарий | Схема не проверяется машиной против реализации; расхождение ловится только тестами и приёмкой | Второй потребитель API или генерация клиентов |
| Пути — snake_case | Дефисы: `/api/session-trace`, `/api/agent-catalog`, `/api/result-repositories`, … | Устоявшаяся история маршрутов до конвенции; дефисы читаемее в URL | Несовпадение стиля с конвенцией; смешение при добавлении новых маршрутов | Переименование маршрутов — только вместе с внешней публикацией API (ломающее изменение для страницы) |
| Абсолютные пути ФС в теле/ответе, не в query | Пути в query: `/api/fs/list?path=`, `/api/fs/git?path=`, `/api/result-repositories/inspect?path=` | Локальный инструмент выбора папки; путь — не секрет в этой модели доверия, журналов доступа вне машины нет | Путь виден в истории браузера и в любых логах адресов, если они появятся | Появление внешних журналов доступа или вынос API с loopback |
| В ответах только машинные значения, подписи — на клиенте | Подписи для человека рядом со значениями: `_label`, `label`, `title`, `model`/`effort_name` | Один клиент на одном языке владельца; сервер уже знает каноническую подпись (например, имя модели из каталога) и дублировать словарь на странице незачем | Локализация подписей невозможна без правки сервера | Второй язык интерфейса или внешний потребитель |

## Что из конвенции соблюдается

Для ясности — правила, которые проект выполняет: единый префикс `/api/`, существительные во множественном числе в коллекциях, корректные методы и коды (`GET` без эффектов, `POST`/`PUT`/`DELETE`, 400/403/404/413/415/502/503), машинный код ошибки (`code`, добавлен задачей 326), отказ на неизвестный query-параметр (400 `invalid_parameter`, задача 326), `Content-Type` у JSON-ответов, `Cache-Control: no-store`, пределы размера тел.
