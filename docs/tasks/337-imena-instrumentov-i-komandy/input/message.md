# 337. Имена инструментов без префикса; команды /cmd и //cmd

## Чего хочет владелец

Владелец, 2026-11-28: два решения по неймингу.

### Инструменты

Убрать префикс `canopus_` из имён MCP-инструментов. Префикс нужен был в плагине OpenCode (общее пространство). В хабе пространство контролируется — коллизий нет. Доноры работают без префикса (Codex `goal`, Kimi `TodoList`).

Новые имена: явные, без бренда, без двусмысленности. Алиасы старых имён — на стороне хаба для совместимости; модели показывать только канонические.

Кандидаты (уточнить при реализации):

| Старое | Новое |
|---|---|
| canopus_send | send_message |
| canopus_task | task |
| canopus_wait | wait_event |
| canopus_watch | watch |
| canopus_next | next_message |
| canopus_doctor | doctor |

### Команды

Два слоя команд в поле ввода:

- `/cmd` — команда Канопуса. Хаб перехватывает, агент не видит. Автодополнение по `/` в начале ввода: название, описание, аргументы. Неизвестная — предложение исправить или отправить как текст. Пользовательские команды — в том же меню с отметкой источника.
- `//cmd` — туннель к агенту. Хаб снимает один слэш и отправляет `/cmd` агенту как его родную команду. Хаб не ищет среди своих. Если агент не поддерживает slash-команды — его ответ будет обычным текстом (не ошибка хаба).

Примеры: `/task` — задачи Канопуса; `//artifact` — команда artifact агента; `/autopilot on` — автопилот Канопуса.

## Красные тесты

Инструменты: модель видит только новые имена; вызов по старому имени (алиас) работает; журнал записывает каноническое имя.

Команды: `/task` перехватывается хабом (агент не получает); `//artifact` доходит до агента как `/artifact`; неизвестная `/xyz` — предложение исправить; автодополнение показывает команды Канопуса; `//` не показывает автодополнение Канопуса.

## Границы

Не меняет протокол ACP. Не добавляет новые команды (только переименование и маршрутизацию). Список команд Канопуса — существующие функции, оформленные как `/cmd`.
