## Суть

opencode (v2 main) передаёт компакцию через ACP стандартными апдейтами: `compaction_update` (in_progress / completed / cancelled / failed) и `compaction_summary_chunk`, а старым клиентам — `session_info_update` с `_meta["opencode/compaction"]`. Наш комментарий в `canopus_task_hub.nv:567` («протокол не имеет события компакции») устарел: событие есть, но не у всех агентов — эвристика остаётся запасным путём для бэкендов без него (kimi и др.).

## Что нужно

1. **Проектор** (`src/acp/project.nv`): вид `compaction_update` → проекция `agent_compaction` (статус; поля — сверить с клоном `%TEMP%\opencode-readonly`, при отсутствии клона восстановить shallow-клоном sst/opencode).
2. **Хаб** (`src/server/canopus_task_hub.nv`): на `agent_compaction` — запись `context_compacted` в журнал с источником `source: "agent"` (сейчас `{before, after, at}`; источник эвристики — `source: "usage_drop"`); серая строка в ленту по завершению, как у эвристики; обновить `signals.nv`.
3. **Эвристика остаётся** (запасной путь для агентов без апдейта); двойная запись на один спад не допускается: если `agent_compaction` завершён, эвристический детект того же спада пропускается.
4. **Тесты**: `src/acp` — проекция нового вида (fake-agent с `compaction_update`); `src/server` — журнал `context_compacted` с `source: "agent"`; прежние тесты эвристики зелёные.

## Критерии приёмки

- `nova test src/acp src/server` зелёные (по п. 7–9 AGENTS.md, с учётом нагрузки машины).
- Проба «подсунь негодное»: fake-agent шлёт `compaction_update: failed` → записи с `source: "agent"` нет, эвристика продолжает работать.
