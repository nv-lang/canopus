# CLI-запрос к хабу: canopus ask

## Чего хочет владелец

Владелец, 2026-11-27, чат интегратора: точка входа «человек → хаб» без браузера — разовый запрос под конкретную модель из терминала и скриптов. «По рекомендации» — завести.

## Что нужно

Команда приложения `canopus ask --agent <id> [--model <m>] [--session <id>] "текст"`:

- находит или создаёт сессию через существующий HTTP API хаба (loopback, порт из конфига инстанса); `--session` продолжает существующую;
- отправляет сообщение, стримит ответ в терминал (текст агента по мере прихода), по завершении хода выходит с кодом 0; отказ/таймаут — честный ненулевой код и причина из `code` ошибки API (326 уже дал машинные коды);
- никакой своей логики процесса: ход ведёт хаб как обычно (машина, журнал, дедлайны) — CLI тонкий клиент (ADR-0018); сообщение, поданное через CLI, видно в веб-ленте той же сессии и наоборот;
- флаги минимальны; неизвестный флаг — ошибка, не молчание (принцип 326).

Красные тесты: запрос через CLI появляется в ленте той же сессии (и события хаба видны CLI); `--session` несуществующей → честный отказ с кодом; хаб не поднят → понятная ошибка соединения, не висяк (свой таймаут подключения).

## Границы

Не интерактивный чат-клиент (пейджер/REPL — потом, если понадобится), не обход API (никаких прямых записей в журнал). Live-стриминг — по существующему каналу страницы (тот же WS/SSE, что у веба), без нового протокола.
