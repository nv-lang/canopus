# 338. Выбор машины при создании сессии по образцу bb

## Чего хочет владелец

Владелец, 2026-11-28: выбор демона при старте сессии — как в bb. Донор: `apps/app/src/components/pickers/EnvironmentPicker.tsx`, `thread-environment-placement.ts`, `thread-default-policy.ts` (пин a08e116, разбор docs/research/2026-11-26-bb-architecture.md §6).

## Что нужно

1. **Пикер машины в поле ввода** (не отдельная форма): при создании новой сессии рядом с выбором модели — выпадающий список машин из `daemon.json`. Показывает: имя, адрес, статус связи (зелёный/серый), последний контакт.
2. **Привязка проекта к машине:** в конфиге проекта (`.canopus/config.json` или `daemon.json`) поле `default_daemon` — id демона по умолчанию для этого проекта. Если не задан — первый в списке.
3. **Наследование детьми:** дочерняя сессия (подзадача, `-cNN`) получает демона родителя автоматически. Переопределение — явным выбором.
4. **Статус связи:** хаб периодически проверяет доступность каждого демона (ping/TCP) и показывает в пикере. Недоступный — серый, выбор возможен с предупреждением.

Красные тесты: пикер показывает список демонов со статусом; проект с `default_daemon` выбирает его; дочерняя сессия наследует демона родителя; недоступный демон серый; смена выбора до отправки работает.

## Границы

Только UI и логика выбора. Протокол демона и журнал не меняются. Не auto-provisioning машин (это enrollment 329 этап 3).
