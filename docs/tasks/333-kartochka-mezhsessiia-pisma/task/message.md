# 333. Карточка межсессионного письма в ленте

## Чего хочет владелец

Владелец, 2026-11-28, чат интегратора («да» на предложение): письма между сессиями (`canopus_send`) должны отображаться в ленте отдельной карточкой, а не плоской служебной строкой, неотличимой от сообщения пользователя. Разбор bb (doc/research/2026-11-26-bb-threads.md) показал: у bb это просто текстовый префикс `[bb message from thread:…]` в обычном пузыре — Канопус делает лучше, а не копирует.

## Что нужно

В ленте сессии письмо от другой сессии рендерится карточкой:

- **Шапка:** имя и id сессии-отправителя как ссылка на её диалог (идентичность сессии — действующая норма философии: ссылка открывает тот же диалог с историей); вид письма: вопрос (qN), ответ на qN, обычное, wake, срочное (пометка 324).
- **Тело:** текст письма; длинный текст сворачивается (как диффы: показать/скрыть).
- **Отличие от слов владельца** видно без чтения текста (иконка/цвет/рамка — по существующей палитре UI).
- В списке сессий — счётчик непрочитанных писем у сессии (данные: `canopus_inbox`, флаг taken).
- Старые журналы: прежняя строка `[canopus] Письмо от …` распознаётся и рендерится той же карточкой (проекция по формату строки, без миграции журналов).

Красные тесты: письмо с qid → карточка с видом «вопрос» и ссылкой на отправителя; срочное письмо → пометка срочности; длинное письмо свёрнуто; прежний формат строки → та же карточка; счётчик непрочитанных растёт и сбрасывается при открытии.

## Границы

Не меняется протокол писем и журнал (только проекция и рендер). Не делается вложенный показ хода чужой сессии (отдельная идея, если понадобится). Стиль — по technical-writing.md для всех новых строк UI.

## Проверка

Веб-тесты рендера по фикстурам событий + живая проба: письмо между двумя тестовыми сессиями выглядит карточкой, ссылка открывает диалог отправителя.
