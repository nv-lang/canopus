# 339. Перенос сессии на другой демон

## Чего хочет владелец

Владелец, 2026-11-28: возможность перенести существующую сессию с одного демона на другой.

## Что нужно

1. **Команда `/move <демон>`** (или кнопка в UI): останавливает агента на текущем демоне, формирует handoff-контекст (механика 324/332), запускает агента на целевом демоне с этим контекстом, обновляет привязку сессии в журнале.
2. **Журнал:** событие `session_migrated {from_daemon, to_daemon, reason}` — видимое в ленте. Старые кадры остаются в истории. Новый агент получает handoff-контекст с подтверждёнными результатами.
3. **Условия:** перенос только при закрытом ходе (активный ход — сначала cancel через 324); целевой демон доступен; проект имеет источник на целевой машине (или cwd задан в daemon.json).
4. **Видимость:** в списке сессий — текущий демон сессии; после переноса — новый.

Красные тесты: перенос с local на selectel — агент на selectel получает контекст, сессия продолжается; перенос при активном ходе — отказ с причиной; недоступный целевой демон — отказ; событие session_migrated в журнале; двойной перенос (A→B→A) работает.

## Границы

Не миграция файлов между машинами (файлы проекта готовятся отдельно, cwd в daemon.json). Не автоматический перенос при отказе демона (это 332 + выбор машины).
