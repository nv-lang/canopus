# 336. Автотекст следующего сообщения (инструмент canopus_next)

## Чего хочет владелец

Владелец, 2026-11-28: в поле ввода сообщения показывается серый автотекст (ghost text). Пользователь нажимает TAB — автотекст заполняет поле. Начал печатать — автотекст исчезает. Без дополнительных LLM-запросов. Механизм — MCP-инструмент `canopus_next`.

## Что нужно

- **Инструмент `canopus_next(prompt: str)`** в наборе инструментов хаба. Агент вызывает, когда хочет предложить пользователю текст следующего сообщения.
- Хаб записывает событие `next_suggestion {prompt, turn, session}` в журнал.
- **UI:** поле ввода показывает `prompt` как серый ghost text (как подсказка Copilot/Codex). TAB — заполняет поле. Печать — скрывает. Enter с заполненным полем — отправляет.
- Ghost text привязан к сессии и ходу. Новый ход — старый ghost text сбрасывается. Несколько вызовов в одном ходу — берётся последний (или первый — решить по простоте).
- Ghost text — предложение, не подтверждение вопроса и не разрешение. Ворота владельца не обходятся.
- Инструкция агенту в системном промпте: «если хочешь предложить следующее сообщение — вызови canopus_next(prompt); prompt от лица пользователя, с учётом принятых решений».

Красные тесты: вызов canopus_next → событие в журнале → ghost text в поле; TAB заполняет поле точным prompt; печать скрывает ghost text; после нового хода ghost text исчез; вызов без prompt — ошибка инструмента; старые журналы без событий — поле пустое.

## Границы

Не генерируем подсказку отдельным запросом. Агент не обязан вызывать. Не кнопки/чипы — только ghost text в поле ввода. Стиль — technical-writing.md.
