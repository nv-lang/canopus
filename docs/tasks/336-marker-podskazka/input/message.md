# 336. Подсказка следующего сообщения (инструмент canopus_next)

## Чего хочет владелец

Владелец, 2026-11-28 («да», затем уточнение): владелец жмёт чип вместо набора текста. Без дополнительных LLM-запросов. Механизм — MCP-инструмент `canopus_next`, не текстовый маркер: хаб контролирует инструменты агента, tool_call уже типизирован в ACP, парсинг текста не нужен. Улучшено вторым мнением (gpt-6.1-sol) и решением владельца об инструменте.

## Что нужно

- **Инструмент `canopus_next(label str, prompt str)`** в наборе инструментов хаба (рядом с `canopus_send`, `canopus_task`). Агент вызывает, когда хочет предложить пользователю следующее сообщение.
- Хаб записывает вызов как типизированное событие `next_suggestion {label, prompt, turn, session}` в журнал. Ответ агенту — подтверждение записи, не команда продолжать.
- **UI:** после завершения хода рисует чипы из событий `next_suggestion` этого хода. Каждый чип отправляет свой `prompt` как `user_message`. После выбора остальные чипы неактивны. После нового хода старые чипы отключаются.
- Двойной клик и повторная доставка не отправляют дважды (дедуп по сессии+ходу).
- Чип — предложение текста, не подтверждение вопроса и не разрешение действия. Ворота владельца не обходятся.
- Инструкция агенту в системном промпте: «если хочешь предложить следующее сообщение — вызови canopus_next(label, prompt); prompt от лица пользователя, с учётом принятых решений».

Красные тесты: вызов canopus_next → событие в журнале → чип в UI; нажатие шлёт точный prompt; два вызова — два чипа, выбор гасит остальные; вызов без prompt — ошибка инструмента; после нового хода старые чипы неактивны; двойной клик — одно сообщение; старые журналы без событий — как прежде.

## Границы

Не генерируем подсказку отдельным запросом. Агент не обязан вызывать. Стиль — technical-writing.md.
