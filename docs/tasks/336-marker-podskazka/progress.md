## Решения

- Владелец, 2026-11-28, уточнение интегратора в текущем чате — «вместо текстового маркера :canopus-next[…] — MCP-инструмент canopus_next».
- Владелец, 2026-11-28, уточнение интегратора в текущем чате — «TAB — заполняет поле. Печать — скрывает». Инструмент принимает только `prompt`. Итоговые критерии записаны в [карточке задачи](input/message.md) на `f5212819`.

## Результат

Хаб предлагает агентам с HTTP MCP инструмент `canopus_next(prompt)`. Инструкция приходит перед первым запросом. Хаб привязывает `next_suggestion {prompt, turn, session}` к открытому ходу и записывает событие в журнал.

После успешного завершения хода пустое поле ввода показывает последнее предложение серым. Tab подставляет текст в черновик. Печать скрывает предложение. Новый ход сбрасывает подсказку. Enter отправляет черновик через обычный путь `user_message`.

## Приёмка

Из дерева задачи с Nova Oracle 0.1.7 и Node 24:

```sh
nova build src/canopus.nv -o target/canopus &&
node src/server/test/next-suggestion.mjs target/canopus &&
node --test --test-concurrency=4 'src/web/test/*.test.mjs'
```

## Проверки

- Сборка Nova Oracle 0.1.7 прошла. Сквозной тест с HTTP MCP, файловым журналом и WebSocket подтвердил восстановление предложения после перезапуска, ошибку при отсутствии `prompt` и точный текст отправки.
- Веб-набор — 658 тестов прошли. До правки интерфейса три новых теста падали на отсутствии автотекста.
- Chromium на ширинах 1360 и 420 px подтвердил наложение на поле, подстановку по Tab, отправку по Enter, скрытие при печати и сброс при новом ходе.
- Предварительный общий Nova-прогон выявил сбои тестов прелюдии планирования, словаря ACP (`daemon_revoked`), Linux-пробы таймаута Git (`ping -n 5`) и ошибку генерации `Vec.join` в тестовом наборе. Проверка числа MCP-инструментов обновлена с учётом нового инструмента. Приёмка выше прошла на итоговом варианте.
- Реальных провайдеров и PostgreSQL не проверяли.
