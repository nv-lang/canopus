# Срочная поправка владельца в активный ход (cancel+resume, «бедный steer»)

## Чего хочет владелец

Владелец, 2026-11-26, чат интегратора: срочную поправку («стоп, не тот файл») сейчас можно внести только прерыванием хода; steer по ACP нереализуем переносимо (спайк [doc/research/2026-11-27-steer-acp-spike.md](../../../research/2026-11-27-steer-acp-spike.md): Kimi честно отказывает `-32600`, Codex молча вешает ход). Зато cancel+resume работает у обоих агентов за ~20–30 мс и ложится на существующие механизмы (`cancel_request`, `@handoff_context`). Владелец, 2026-11-27: «по рекомендации» — завести задачу.

## Что нужно

Слово владельца (и письмо `canopus_send` с пометкой срочности) может попасть в **активный** ход через предварительную отмену: хаб отменяет ход (`cancel_request`), немедленно продолжает диалог новым ходом со склейкой контекста через handoff + вставкой поправки. Машина `dialog.alula` имеет оба перехода — таблицу менять не нужно (проверить спайком-фактом из документа).

Красные тесты:
- поправка, поданная при открытом ходе, доезжает в тот же диалог следующим ходом, журнал показывает cancel+resume отдельными событиями;
- отказ агента на cancel → честный откат: поправка встаёт в очередь (сегодняшнее поведение), владелец видит причину;
- поздние ответы оборванного хода помечаются `stale` (существующий протокол), двойного исполнения нет.

## Границы

Не steer-пасsthrough (агенты не умеют), не изменение атомарности обычного хода: без поправки ход по-прежнему атомарен. По ADR-0018 срочное слово владельца — функция процесса, не механизм агента.
