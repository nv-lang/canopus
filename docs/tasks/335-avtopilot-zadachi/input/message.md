# 335. Автопилот задачи: событийное продолжение до критерия закрытия

## Чего хочет владелец

Владелец, 2026-11-28, чат интегратора («по рекомендации»): последнее звено философии «Канопус отвечает за задачу до её закрытия» — задача продолжается сама, без напоминаний владельца, до критерия закрытия. Основание: [исследование автономного режима bb](../../../research/2026-11-28-bb-autonomous-mode.md) и [синтез целей](../../../research/2026-11-22-goals-synthesis.md).

## Что нужно

Событийный цикл в хабе, рядом с `@task_continue`:

- После каждого завершённого хода задачи хаб механически проверяет критерий закрытия из карточки задачи (команда или страж, не LLM).
- Критерий не выполнен и нет препятствий — продолжение служебным ходом с причиной из предыдущей проверки.
- Остановка с видимой причиной (словарь 322): критерий выполнен, вопрос владельцу, бюджет исчерпан, три неуспеха подряд, ручной стоп.
- Дедуп продолжений через журнал: один владелец продолжения, 310 и 332 не запускают параллельных продолжений того же падения.

Красные тесты: автопилот не продолжает при неотвеченном вопросе владельцу; ручной стоп отключает до возобновления; выполненный критерий закрывает без лишнего хода; два механизма не продолжают одно падение дважды; каждая остановка имеет непустую причину.

## Исполняемый критерий закрытия (дополнение, второе мнение 2026-11-28)

Карточка задачи может содержать блок:

    ## Критерий закрытия
    ```check
    check: guards-green
    expect: exit 0
    ```

- **Реестр проверок.** `check` — идентификатор из утверждённого реестра (scripts/checks.toml или аналог), не произвольная команда. Реестр связывает id с командой, параметрами и версией. Произвольный `run` не допускается: карточку может изменить агент.
- **Утверждение.** Критерий связывается с версией реестра; изменение любого аннулирует прежний результат.
- **Изоляция.** Проверка исполняется без сети, секретов и сокетов хоста; с ограничениями CPU, памяти, процессов, времени и объёма вывода. Таймаут завершает всё дерево процессов. Недоступна изоляция — проверка не запускается (честная ошибка, не молчание).
- **Схема.** `expect.exit` обязателен; `contains` — дополнительное условие (ищется в stdout до обрезки). Неизвестные поля и неверный синтаксис — видимая ошибка конфигурации, не молчание.
- **Результат.** Событие в журнал: check_passed / check_failed с хвостом вывода, привязанное к задаче, ходу, версии критерия и состоянию дерева. Последующие изменения дерева делают результат устаревшим.
- **Граница.** Зелёная проверка = «машинный критерий выполнен». Закрытие допускается только при выполнении остальных ворот процесса (приёмка, HOLD, обязательные решения владельца). Проверка тестов сама по себе не доказывает выполнение задания.
- **Счётчик неуспехов.** Хранится в журнале (перезапуск не обнуляет). Сброс — при смене критерия или явном возобновлении владельцем.

Дополнительные красные тесты: несколько блоков, один красный — не закрывает; ошибочная схема — видимая ошибка; недоступное дерево — честный отказ; отказ изоляции — проверка не запускается; убийство дочернего процесса; переполнение вывода — обрезка с пометкой; изменение критерия/дерева во время проверки — результат устаревший; повтор события и восстановление после перезапуска; зелёный критерий при незакрытых воротах — задача не закрывается; красный критерий три раза — пауза со счётчиком; перезапуск между попытками — счётчик сохранён.

## Границы

Не судья-LLM и не декомпозиция задач. Не автосоздание задач. Перебор обходных путей — отдельная цель философии.

## Проверка

Красные тесты карточки и живая проба: задача с механическим критерием доезжает до закрытия без сообщения владельца; остановка на вопросе видна причиной.
