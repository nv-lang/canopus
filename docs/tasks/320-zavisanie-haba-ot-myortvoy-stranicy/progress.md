### Выводы

1. Главный множитель простоя — инкрементальный GC Boehm: при срыве `GC_gww_read_dirty` каждая сборка маркирует всю кучу (x3 на 20 сессиях, x1,7 на 75). Сторона Новы (кит 0.1.6).
2. Вторая часть — работа по каждой сессии в каждом проходе цикла (`pump` → `route_pump` → `ct_pump`/`work_allowed` — машина рабочего режима дважды за проход на сессию; `route_observe`/`cs_observe` — каждые 2 с). ~4–5 мс на сессию в секунду при 75 сессиях.
3. `NOVA_GC_INCREMENTAL=0` — только аварийная мера: вдвое дешевле, но паузы до 2 с на активной фазе.
4. Класс «мёртвая страница» (план выше) этими замерами не воспроизводился: проб не было. Отдельная проверка WS-доступности после прогрева — следующий шаг, результаты сюда же.

Инструментация: ветка `task/320-hub-stage-counters` от `origin/main` (коммит `f39871ba`, база `0e6ae77d`), бинарь sha256 `f0ccb258…`, кит Oracle 0.1.6. Логи стенда — во временном каталоге, до уборки.

Прогрев доказан, а не принят по числу строк: кэш индекса удаляется перед стартом, поэтому pending-записи `@restoring` с пустыми метаданными не попадают в индекс. Таймлайн `/api/sessions-index` у обеих сборок совпал: 0 → 5 → 19 → … → 49 на 103 с → 75 на 108 с, три опроса подряд 75 (113/118 с) — дренаж на ~117,7 с; затем оседание 120 с и замер 60 с. Конфиг — явный фиктивный агент (node + fake_agent, путь в песочнице), чтобы исключить запуск штатных агентов владельца на восстановленном ходе.

Схема `/api/sessions-index` — поле `entries`, 75 записей у обеих. Предел Boehm в PE у обеих сборок — 81920 (проверено чекером `check-gc-limit.py`, rc=0). Записей вне песочницы нет: данные и домашний каталог владельца — 0 изменённых файлов за окна прогонов; единственный изменённый файл репозитория — этот журнал.

Вывод: на полном санированном профиле исправление даёт ~1,8× (0,50 → 0,28 ядра), но расход не снят — в простое остаётся ~0,28 ядра при куче ~2,5 ГБ; выигрыш 4,3× с 20-сессионного стенда на большой случай не переносится. Числа на несанкционированной копии (0,85–0,89 ядра) завышены чтением реальных каталогов репозитория по записанным путям — для изоляции они недействительны. По одному замеру на сборку.
