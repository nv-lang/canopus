# 331. Переход каталогов документации и входных материалов

## Требования

REQ-01. Исполнитель переносит весь каталог `docs/` Канопуса в `docs/` с сохранением содержимого документов.
REQ-02. Исполнитель переносит входные подкаталоги задач `input/` в `input/`.
REQ-03. Генераторы и читатели Канопуса используют новые пути для перенесённых проектов.
REQ-04. Для неперенесённого проекта без явного `tasks_dir` Canopus продолжает читать существующий `docs/tasks`.
REQ-05. Для нового проекта без каталога задач Canopus использует `docs/tasks`.
REQ-06. Явный `tasks_dir` сохраняет приоритет над выбором умолчания.
REQ-07. Миграция сначала формирует отчёт без изменения исходных файлов.
REQ-08. Применение миграции требует проверенной резервной копии изменяемых данных.
REQ-09. При конфликте путей или изменении исходных данных миграция останавливается без перезаписи конфликтующих файлов.
REQ-10. Миграция сохраняет номера задач, состояния, HOLD и содержимое вложений.
REQ-11. Миграция обновляет действующие ссылки и записанные пути только внутри выбранного проекта.
REQ-12. Миграция не изменяет имена веток `task/NNN-slug`.
REQ-13. Приватное состояние и временные файлы не попадают в Git.
REQ-14. Повторный запуск миграции не создаёт дубликаты задач и входных материалов.
REQ-15. Исполнитель готовит механизм и порядок миграции остальных проектов после Канопуса.
REQ-16. Проекты с существующим `docs/tasks` также проходят проверку входных подкаталогов.

## Критерии приёмки

AC-01. Стражи проверяют новую раскладку и корректные ссылки.
AC-02. Проверки путей подтверждают создание новой задачи и чтение прежней задачи в неперенесённом проекте.
AC-03. Проверки миграции подтверждают сохранность бинарных вложений, настроек и HOLD.
AC-04. Проверки конфликтов, повторного запуска и изменившегося источника исключают потерю данных.
AC-05. Полные наборы затронутых частей проходят до публикации результата.
AC-06. Интегратор проверяет показ задач живым хабом после разрешённого обновления.

## Границы

DNC-01. Исполнитель не обновляет живую основную копию без отдельного слова владельца «обновляй».
DNC-02. Исполнитель не перезапускает сервис владельца.
DNC-03. Исполнитель не публикует приватную инвентаризацию проектов.
DNC-04. Исполнитель не переписывает историю Git и исходные цитаты владельца.

## Результат и куда он попадает

Действующие пути, переходная политика и порядок применения находятся в Каноне и руководстве миграции.
Механизм миграции находится в `scripts/`.
Код генераторов, читателей и стражей использует согласованные пути.
Папка задачи хранит историю реализации и проверок.
