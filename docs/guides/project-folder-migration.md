# Перенос каталогов проекта

Интегратор переносит `doc/` в `docs/` и входные подкаталоги задач `task/` в `input/`.
Решение владельца от 2026-11-28 распространяется на все проекты.
Интегратор переносит Канопус первым.
Интеграторы остальных проектов выполняют переход после проверки Канопуса.
Ветки `task/NNN-slug` сохраняют имена.

## Подготовка

Интегратор составляет приватную опись проектов.
Для каждой записи интегратор указывает абсолютный `root`.
Если проект использует явный или унаследованный `tasks_dir`, интегратор указывает его в записи.
Интегратор хранит опись и отчёты вне публичного репозитория.

Пример файла описи:

```json
[{"root":"C:/work/project","tasks_dir":"doc/tasks"}]
```

Интегратор включает в опись и проекты с существующим `docs/tasks`.
В таких проектах механизм проверяет входные подкаталоги задач.
Для активных рабочих деревьев интегратор отдельно проверяет незакоммиченные изменения.
Интегратор не переносит чужие рабочие деревья автоматически вместе с основной копией.

## Отчёт без применения

Интегратор запускает команду из каталога, который не будет перенесён:

```sh
python C:/work/canopus/scripts/migrate-project-folders.py --projects projects.json --report migration-report.json
```

Механизм перечисляет переносы и изменяемые файлы с SHA-256.
Механизм отказывает при конфликте каталогов, символьных ссылках или активных записях задач.
Механизм не меняет файлы проекта без `--apply`.
Для дополнительных JSON-журналов сессий интегратор передаёт повторяемый `--state-file`.
Механизм обновляет пути и внутри JSON-текста события без контрольной подписи.
Механизм сохраняет историю, подтверждения, HOLD и принятые события приложения без изменения.
Интегратор не передаёт подписанные native-формы как изменяемые журналы.
Интегратор не передаёт журналы чужого экземпляра.

## Применение

До изменения живой системы интегратор получает слово владельца «обновляй» по [AGENTS.md](../../AGENTS.md).
Владелец останавливает сервисы по правилам проекта.
Интегратор проверяет остановку записывающих процессов.
Интегратор освобождает каталоги, которые предстоит перенести.

```sh
python C:/work/canopus/scripts/migrate-project-folders.py --projects projects.json --report migration-report.json --apply --backup migration-backup
```

Механизм требует новый каталог резервной копии вне репозиториев переносимых проектов.
Механизм сохраняет исходные байты изменяемых файлов и манифест.
Механизм проверяет контрольные суммы до первого переноса.
Механизм проверяет итоговые контрольные суммы после записи.
Механизм сохраняет номера, статусы, HOLD и содержимое бинарных вложений.
Файл `verified.json` в резервной копии подтверждает завершение проверки.
При ошибке интегратор сохраняет отчёт и резервную копию для восстановления.
Интегратор не удаляет оставшиеся данные до проверки причины ошибки.
Повторный запуск после успешного перехода не создаёт новую задачу или копию вложения.

Интегратор проверяет Git diff перед коммитом.
Интегратор коммитит документы и допустимые входные материалы.
Интегратор оставляет приватное состояние, опись, отчёты с локальными путями и резервную копию вне Git.
Механизм не коммитит изменения за интегратора.

Если Git уже перенёс отслеживаемые документы, прежний `doc/` может содержать оставшиеся приватные файлы.
Для этого случая интегратор указывает `"tracked_moved": true` в записи проекта.
Механизм проверяет отсутствие отслеживаемых файлов под `doc/`.
Механизм переносит оставшиеся файлы по одному без перезаписи конфликтующего назначения.
Механизм удаляет только опустевшие прежние каталоги.
Этот режим нужен для runtime-данных Канопуса после разрешённого `ff-only` обновления.
До завершения переноса интегратор не запускает сервисы.

## Проверка результата

Интегратор проверяет ссылки и стражи проекта.
Интегратор сверяет бинарные вложения по манифесту.
Интегратор проверяет выбранный набор профилей и настройки проекта.
После разрешённого обновления владелец перезапускает сервис.
Интегратор проверяет список задач и открытие входных материалов.
Для ещё не перенесённых проектов продолжает действовать [переходный выбор `tasks_dir`](../canon/configuration.md#каталог-задач-и-переход).

Механизм переносит каталоги и локальные ссылки документации.
Генераторы и читатели путей других проектов их интеграторы обновляют по собственному diff.
Механизм не заменяет слова `task` в именах веток или прикладных понятиях.
