# Как bb работает с целями: цели как extension-state провайдера, пауза при interrupt, ретраи (исследование 2026-11-26)

Раздел «что перенести» отобран по критериям [doc/research/README.md](README.md).

Повод: владелец назначил bb **главным донором** проекта. Источник — открытый репозиторий `get-bb/bb`, клон только
для чтения вне репозитория, тег **`desktop-v0.50.1`** (ровно та версия, что установлена у владельца),
ревизия **`a08e116566d1785bc04578a866df8a0359157dd4`** (TypeScript; ядро — `packages/`, провайдеры и плагины —
`plugins/`). Отдельные плагины при нужде пинятся своими тегами (`plugin-github-v0.2.0`, `plugin-memory-v0.2.0` и т.д.).
Всё ниже — чтение исходников, без запуска.

Обозначения: **[V]** — проверено по коду (путь:строка); **[I]** — вывод.

## Главное

- **Своей системы целей у bb нет — есть интеграция чужой (Codex-native) системы Goal.** bb — оркестратор поверх
  провайдеров (Codex, Claude Code, ACP-агенты); понятие Goal существует только у провайдера Codex
  (app-server методы `thread/goal/*`). bb транслирует нотификации Codex в своё событийное хранилище, рисует
  карточку и проксирует управление. Судья завершения, автопродолжение и enforcement бюджетов — внутри Codex. **[V]**
- Для остальных провайдеров (Claude Code, ACP) понятия цели нет вовсе: composer-actions у Claude — только
  `["plan"]` (`plugins/provider-claude-code/server.ts:118`), у Codex — `["plan", "goal"]`
  (`plugins/provider-codex/server.ts:83`). **[V]**
- bb-собственные механизмы «автономности» — плагины **automations** (cron/one-shot расписания) и
  **provider-retry** (авто-ретрай упавших ходов). **[V]**
- Архитектурная рамка: «Provider-specific concepts (Codex goals…) are that plugin's extension kinds… Core keeps
  no table of tool names» (`docs/provider-plugin-api.md:363-369`) — цель живёт как **thread-scoped extension
  state**, а не сущность ядра. **[V]**

## 1. Codex Goal в bb (сквозной путь)

- **Кто ставит:** пользователь — текст `/goal <objective>` в композере; любой `/goal`-текст, не являющийся
  resume/pause/clear, «goes to Codex as a normal prompt» — цель создаёт Codex из промпта
  (`plugins/provider-codex/skills/codex-provider/SKILL.md:19-20`). Модель сама цель не ставит. **[V]**
- **Форма цели:** `ThreadGoal = { threadId, objective, status, tokenBudget, tokensUsed, timeUsedSeconds,
  createdAt, updatedAt }` (`plugins/provider-codex/src/generated/codex-app-server/schema/v2/ThreadGoal.ts:4`). **[V]**
- **Хранение:** источник истины — Codex app-server; bb дублирует последний снапшот как событие
  `thread/extensionState/updated` (kind `provider-codex/goal`) в SQLite-таблицу `events`
  (`plugins/provider-codex/src/delta-translation.ts:1123-1146`; partial index
  `packages/db/drizzle/0106_thread_state_index.sql:2`; семантика «latest snapshot per kind wins» —
  `packages/domain/src/thread-event-scope.ts:153`). **[V]**
- **Статусы (закрытый enum, 6):** `active, paused, blocked, usageLimited, budgetLimited, complete`
  (`plugins/provider-codex/src/extension-kinds.ts:11-18`; дубль в ядре
  `packages/domain/src/thread-timeline-goal.ts:3-10`). **[V]**
- **Кто меняет статусы:** Codex — сам (`complete/blocked/budgetLimited/usageLimited`); пользователь через мост —
  `/goal pause|resume|clear` и CLI `bb thread clear-goal` (`plugins/provider-codex/src/bridge/bridge.ts:2352-2410`,
  `apps/cli/src/commands/thread/actions.ts:686`). Правила валидации в мосте: pause только из active
  («The Goal is not active, so there is nothing to pause.» `bridge.ts:2395-2398`), resume нельзя из
  active/complete («The Goal is already …» `bridge.ts:2403-2405`), нет цели — «This thread has no Goal to …»
  (`bridge.ts:2382-2383`). **[V]**
- **Бюджеты:** `tokenBudget` (nullable) + счётчики `tokensUsed`, `timeUsedSeconds` — считает и enforce'ит Codex;
  bb только отображает «used / budget tokens» и длительность (`plugins/provider-codex/src/goal-card.tsx:35-41,74-83`). **[V]**
- **Пауза при interrupt — инвариант моста:** при остановке треда bb **сначала ставит Goal на паузу**, чтобы Codex
  не перезапустил её следующим сообщением: `if (session.goalStatus === "active") await
  pauseActiveGoalForInterrupt(...)` (`bridge.ts:2260-2261,2328-2348`; SKILL.md:15-16). **[V]**
- **Resume из paused:** `/goal resume` ставит статус active и запускает ход с grace-периодом
  `GOAL_RESUME_TURN_GRACE_MS = 5_000` (`bridge.ts:1857,2060-2061`). **[V]**
- **Clear с подтверждением:** runtime после `thread/goal/clear` ждёт подтверждающее событие от провайдера с
  таймаутом (`RuntimeThreadGoalState.waitForGoalClear`,
  `packages/agent-runtime/src/runtime-thread-goal-state.ts:39-85`; вызов
  `packages/agent-runtime/src/runtime.ts:2332-2367`). Команда считается выполненной только по событию, а не по
  отправке запроса. **[V]**
- **Перезапуск:** состояние переживает рестарт — оно событие в БД; при resume сессии мост перечитывает цель у
  Codex (`thread/goal/get`, `bridge.ts:2374-2381`). Capabilities хендшейка: `threadGoalClear: true` только у
  Codex (`docs/provider-bridge-protocol.md:58`). **[V]**
- **Форк:** специальной обработки goal при форке в bb нет — состояние живёт на стороне Codex-треда; форк
  checkpoint'ами (`capabilities.fork: "checkpoint"`). **[V]** (по отсутствию кода — [I]).
- **UI:** thread-scoped composer-баннер `CodexGoalBanner` через
  `experimental_useThreadExtensionState(threadId, "goal")` (`goal-card.tsx:43-93`); заголовки: «Goal»,
  «Goal paused», «Goal blocked», «Goal usage limited» (`goal-card.tsx:14-18`); active рисуется «в рабочем стиле»,
  complete/budgetLimited/cleared не показываются (`plugins/provider-codex/src/goal-card.test.tsx:53-72`). **[V]**

## 2. Automations (bb-native, cron)

- «An automation is a scheduled task. When due it runs in one of two modes: agent — spawn a thread or re-prompt a
  target thread with a configured prompt; script — run a stored server-side script»
  (`plugins/automations/skills/automations/SKILL.md:8-11`). **[V]**
- **Кто ставит:** пользователь или агент через `bb automation create`; изнутри треда — origin `agent`.
  **Защита от рекурсии:** «Threads created by automations cannot create automations, and neither can a thread
  while an automation run is executing in it» (SKILL.md:15). **[V]**
- **Хранение:** своя SQLite (better-sqlite3): `next_run_at, run_count, consecutive_failures, last_run_status,
  last_error` (`plugins/automations/src/data.ts:22-36`) — переживает рестарт. **[V]**
- **Тихий тик:** пустой stdout или последняя строка `{"wakeAgent": false}` → «skipped silent tick»
  (SKILL.md:23). **[V]**
- **Бюджеты:** только технические — таймаут скрипта 120 с по умолчанию / 900 с максимум, quick-retry до 2 раз с
  backoff 30 с (`plugins/automations/src/limits.ts:11-14`, `src/data.ts:56-57`). Бюджетов ходов/токенов у
  agent-автоматизаций нет. **[V]**

## 3. Provider-retry (bb-native, автопродолжение упавших ходов)

- Ретраит провалившиеся ходы Codex/Claude Code: «queues a retry of the failed turn, which core runs by
  continuing accepted input or re-sending input the provider never accepted»
  (`plugins/provider-retry/skills/provider-retry/SKILL.md:8-12`). **[V]**
- Три класса сбоев: overload (экспоненциальный backoff), 5xx/обрыв (~минута, удвоение), subscription-window limit
  (ретрай после открытия окна с джиттером) (SKILL.md:14-21). **[V]**
- **Бюджет:** «A turn gets at most four automatic retries»; настройка `maximumWait` (6 ч дефолт) отсекает
  слишком далёкие reset'ы; кредитные лимиты не ретраятся (SKILL.md:37-40). **[V]**
- **Хранение:** pending retry — «ordinary durable queued row… survives restart» (SKILL.md:42-43); виден на
  queue-карточке треда с причиной и временем; одна pending-запись на тред. **[V]**
- **Дедупликация через RPC-«решение»:** плагин публикует решение через RPC `decision.get`; другие плагины
  (Automations, Workflows) ждут его до минуты, чтобы не дублировать ретрай (SKILL.md:29-35). **[V]**

Судей/верификаторов завершения (judge/verifier как отдельный агент) в bb нет. **[V]** (по отсутствию — [I]).

## 4. Ключевые тексты

Промптов-«system reminder» про цели у bb нет (goal-логика — внутри Codex CLI). Пользовательская документация
поведения (`plugins/provider-codex/skills/codex-provider/SKILL.md:15-21`):

> "Stopping a running Codex thread pauses its active Goal… Send `/goal resume` to make a paused, blocked, or
> usage-limited Goal active again; Codex starts working on it in that message's turn. `/goal pause` and `/goal
> clear` pause or remove the Goal without starting a turn, and any other `/goal` text goes to Codex as a normal
> prompt."

Строки UI (`goal-card.tsx:14-18`): «Goal», «Goal paused», «Goal blocked», «Goal usage limited»; ошибки моста:
«This thread has no Goal to {command}.» (`bridge.ts:2383`), «The Goal is not active, so there is nothing to
pause.» (`bridge.ts:2397`), «The Goal is already {status}.» (`bridge.ts:2404`). **[V]**

## Что перенести в Канопус (отбор по критериям README)

1. **Цель как thread-scoped extension state, а не сущность ядра.** Ядро хранит generic-событие
   `thread/extensionState/updated` (kind + payload + схема плагина, «latest snapshot per kind wins»); карточку
   рисует плагин. Persistence, реплей и UI — почти бесплатно. Согласуется с нашим решением «цель в журнале
   сессии событиями» (синтез, раздел 2). **[I]**
2. **Закрытый enum статусов с бюджетными терминальными состояниями:** `usageLimited`/`budgetLimited` отделены от
   `blocked` — видно, *почему* цель встала, и `resume` легален именно из них. У нас — те же шесть статусов
   (синтез, раздел 1). **[I]**
3. **Пауза цели при interrupt как инвариант** (`pauseActiveGoalForInterrupt`): остановил тред — цель автоматически
   paused, иначе следующее сообщение молча перезапустит автономную работу. Прямо переносимо в хаб. **[I]**
4. **Clear с подтверждением через событие** (`waitForGoalClear` с revision + timeout) вместо «отправил и забыл». **[I]**
5. **Команды-глаголы над целью без запуска хода** (`/goal pause|clear` не стартуют turn, `/goal resume` стартует) —
   дешёвое управление без побочных эффектов. **[I]**
6. **Дедупликация автопродолжений через RPC-«решение»** (`decision.get`): один владелец ретрая, остальные ждут —
   снимает гонки «кто перезапускает упавшую работу». Родственно нашему fence из синтеза (раздел 3). **[I]**
7. **Защита от рекурсии автономности** в automations (автоматизация не может создать автоматизацию из запущенного
   ею треда) — простое правило против самопорождающихся циклов. **[I]**
